# 能力组合分发

本说明解释能力商店的实际程序接口，不作为运行时规则来源。

作者源在 `ksf-source.yaml` 协议2中用 `distribution.entries` 列出发布入口。一般以搭档为入口，其精确 `references` 指定下挂基本功、数据包及必要资源。四类对象保留独立ID和版本，随入口的依赖闭包一起发布；未声明入口的源保留独立分发。安装依赖不等于每次采用都加载资料全文。

从源目录调用 `ability-store pack` 选择入口，生成兼容v1完整包；显式选择 `protocol: "ksf-ability-package-v2"` 可导出分组包。通过 `items` 选择不同实际来源时使用v2。包记录完整定义、资源、根项、精确依赖和内容身份，不能以绑定成员为独立入口。共享成员按稳定ID、版本及内容复用，包选项和传输来源不改变对象内容身份。

源目录通过HTTP分片、Git或本地目录获取。添加和刷新不安装；安装、更新、卸载、个人复制及回退先预览，再携带 `ifMatch`、`planDigest` 和唯一 `operationId` 执行。源整体更新覆盖全部已安装对象，不取当前分页或筛选的列表作为范围。相同请求重试复用操作标识，状态变化后重新预览。

本地/Git更新以实际安装入口为起点，新依赖闭包不再使用的旧自动依赖可退出。独立安装旧项、个人稿、其他来源或当前工作仍需要旧精确版本时，明确拒绝危险切换，保留现状。共享依赖更新按实际连接组联动；无关组可分别报告阻塞与成功。

更新内容须提升相应对象版本并修订入口精确引用。同版本不同内容被拒绝，已知历史身份保留。回退使用已校验的完整安装代次，联动组一起恢复；不改个人稿。源不可达、停用或移除后，已装副本仍可读取，缓存新鲜度与最新状态分别表达。

`ability-store publish` 接收本地包与源声明，冻结版本、包和目录；`verify-published` 从消费者HTTP入口回读。发布工具的本地作者声明不是真实托管身份认证；发布PR仍需核对可信事件中的GitHub用户名与对象ID第二段。同版本历史不能被新包替换。

Core基础能力随Core维护；公用能力源提供可选场景能力。Core不附带公用能力源离线副本，也不在联网失败时以旧随包目录冒充最新结果。正式安装副本、已验证请求缓存和个人能力独立保留。
