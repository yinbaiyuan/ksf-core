# 项目、能力、知识与协作飞轮

四个应用查看与操作各自原件。Agent 沿固定入口确认请求、项目归属与适用能力，再由专业搭档和基本功完成已授权工作。跨域链接表示来源或关联，不自动表示采用、写入或完成。

| 领域 | 原件与状态持有方 | Agent 责任 | 应用责任 |
| --- | --- | --- | --- |
| 项目 | 根卡入口、项目管理主件、执行检查点与实际工程 | 项目规划、推进控制、验收收口；路由只准备归属和事实 | 查看/维护同一管理主件、原文与专业交接 |
| 能力 | 现有四类对象、精确引用、有效来源及用户派生基线 | 能力管理搭档及设计基本功、能力验证与迭代 | 发现、读取、显式维护、结构检查和回到来源 |
| 知识 | 本实例知识 Markdown、组织规则、来源原件 | 知识整理搭档及知识组织方法，内容处理按需选择 | 浏览、搜索、记录、修订、核对显式引用 |
| 飞轮 | 既有报告/建议/审阅业务库和独立执行恢复库 | 工作回顾、改进落实与效果复核 | 证据回顾、处理决定、改进交接和实际结果跟踪 |

runtime 持有请求层连续性、授权、能力安排和整体交付；项目路由持有归属与必要事实；资产维护持有跨域唯一落点和通用写入保障。专业步骤在对应基本功维护，应用和公共程序不再复制一套提示词业务规则。普通局部任务不必经全项目重规划，普通读取不触发知识沉淀。

## 一次改进如何往返

实际项目结果或用户纠正形成有来源的回顾；飞轮提供针对确定目标的具体候选；用户决定或明确授权后，Agent 读取目标最新版本，采用相应专业方法落实；应用读回唯一原件，飞轮记录实际处理和验证；后续项目使用该版本并保留实际结果，飞轮再观察原问题是否复发。没有后续证据时保留“效果尚未观察”。

建议采纳、执行状态、程序检查和真实效果分别表达。应用跳转、任务草稿、文件存在、对象 active 或聊天完成声明都不独立证明采用或业务完成。跨域关系只根据显式来源与声明，不用关键词或时间猜配。

## 公共程序边界

`assets` 是 root 固定的确定性服务，需要 filesystem 权限。对象 list/read/check/write 沿现有对象服务；写入以读取的 definition_digest 为条件，在对象锁内核对，普通系统对象派生为用户副本，固定入口仍拒绝日常改写。关联能力源在本界面只读，回其实际源工程维护。

知识 tree/read/search/save/create/check 使用工作区已有安全路径和版本保存，不跟随符号链接；创建不覆盖，正文保存保留冲突。普通新记录不自动套认知框架；新主题或导航结构由知识方法按实例规则处理。应用只保留浏览/编辑草稿，不建立第二份正文库。

跨域来源按显式 Markdown/Wikilink 核对实际路径，外部网页不自动下载，本根内绝对定位先转换并核实，跨根路径或无法确认项保持未核验。检查文件存在不等于核查行号、锚点、引用语义或来源可信度。使用记录按需核对最近 100 条已准入采集记录，区分声明采用、主目标和明确关联；范围有限或没有记录均不证明未使用。结果未知先读回对账，不盲目重发有副作用的操作。

## 采用的一手实践及取舍

- [Agent Skills 作者实践](https://agentskills.io/skill-creation/best-practices)强调真实任务、项目资料、用户纠正和执行轨迹。KSF 采用这些作为能力候选与修订依据，并按当前步骤渐进读取；不因一次成功自动建立长期方法。
- [Anthropic Agent 评测](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)区分 Agent 声明与环境结果，组合不同评判。KSF 对结构、程序、实际使用和长期效果分层记录；不以模型自评一次通过替代真实验证。
- [Obsidian Bases](https://obsidian.md/help/bases)通过视图操作本地 Markdown 及属性。KSF 采用原件唯一、应用提供视图的边界；不复制四套当前正文或进展。
- [GitHub Copilot Memory](https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory)提供引用复核与作用域思路。KSF 采用来源和使用前复核；正式知识与能力仍由人决定，不照搬自动生成、投票或到期删除。

以上是设计依据与 KSF 的取舍，不证明本次实现已经有效。程序测试、浏览器走查、独立会话和真实长期使用分别由实际项目验收记录持有。Git 提交、推送和正式发行仍按各自授权。
