# 三套元能力设计体系

三项设计基本功分别负责专业方法、持续责任和跨责任合作。它们是可独立使用的完整能力包；能力管理组织整体对象方案，能力诊断提供通用工艺，能力维护将确定变化落实到正确来源。

| 体系 | 独有结果 | 正式入口 |
| --- | --- | --- |
| 基本功设计 | 有依据、可执行、可检查且边界清楚的专业方法 | [基本功设计](../../abilities/competencies/competency-design/competency.md) |
| 搭档设计 | 方法支持真实、交互能推进、结果能收口的责任角色 | [搭档设计](../../abilities/competencies/partner-design/competency.md) |
| 协同设计 | 能交接、能处理变化和返工、能整体完成的合作规则 | [协同设计](../../abilities/competencies/cooperation-design/competency.md) |

每包包括设计原理、结构选型、建设与重构方法、专业检查表、模板、完整样例、评估方法及题库。包内方法资源由对应基本功在主文明确调用和负责；本页说明组成，不建立额外执行流程。

## 如何衔接

[能力管理搭档](../../abilities/partners/ability-manager/partner.md)负责复用、完善、组合或新增的整体方案，并根据需要使用对应设计方法。三种设计不要求固定顺序或每次全部参与；给已有搭档增加一个方法不必再造协同。

[能力诊断](../../abilities/competencies/ability-diagnosis/competency.md)完整保留 better-skill v1.1.0 的创建、体检、重构和比较方法及原始资源。它处理通用工艺，三种设计处理各自专业问题。[能力维护](../../abilities/competencies/ability-maintenance/competency.md)处理来源、版本、资源、依赖和生命周期的实际变更。原能力验证已退出有效 Core 对象。

## 加载和数据

能力管理以 + 引用能力诊断，三种设计以普通引用按需取得诊断，各自必需方法资源由主文指出读取条件。引用不等于执行或采用，读取行为沿[现有展开机制](../cli/context.md)，不增加新的加载层。

这些能力不属于 Runtime 首次固定加载。持续采用时沿现有[工作绑定与增量正文](../runtime/work-context.md)机制恢复；案例、原稿和进展留在任务资料，个人设置只保存实际消费的必要参数。

## 验证与来源

三个包的 evals 保存创建、重构和边界输入、检查标准及触发题，examples 保存完整候选与修订对照。评估中的示例身份只用于隔离材料，不成为现役 Core 对象。对象结构和引用由程序核对，专业可用性由实际案例检验，独立模型效果另按真实记录评估。

三套体系借鉴 better-skill 的完整工艺组织，针对 KSF 对象责任建立原生方法；没有将文件数量、篇幅或上游评级直接作为本地效果结论。
