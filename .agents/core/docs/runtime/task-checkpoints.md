# 项目检查点格式说明

新格式项目在里程碑内使用任务目录及task.md，见[治理协议](../project-management/governance.md)与[任务模板](../project-management/templates/task.md)。本文说明尚未迁移项目的兼容检查点。

旧检查点是项目中的普通 Markdown，默认位置为 `项目/<项目名>/任务/<任务名>.md`，根卡链接指向该记录。保存条件、内容要求、恢复判断、失败处理与实际步骤由 [项目推进控制](../../abilities/competencies/project-control/competency.md#项目恢复暂停与检查点)持有；本文仅解释格式。

管理主件保存现行项目安排，检查点保存具体执行的恢复信息，聊天保留来源原文。它不是第五类能力对象，也不是采集器自动生成的业务记录。

示例元数据如下。它是普通材料格式，不是第五类能力对象，也不使用对象 CLI 管理：

```yaml
---
checkpoint_schema: 1
task_id: "example-task-001"
name: "示例任务"
state: "in_progress"
updated: "2026-10-19T10:00:00+08:00"
---
```

task_id 是任务内稳定的非空标识，改文件名不改标识；示例值不能复制为多个真实任务的身份。state 使用 in_progress、paused、blocked、completed 或 cancelled，仅表达记录状态，不是程序自动执行的状态机。updated 写实际保存时间。遇到未知 schema，先保留原件并说明不支持，不猜测迁移或覆盖。

## 必须能够恢复的信息

正文可以按任务调整章节，但必须能回答以下问题；没有的内容明确写“无”或“未知”：

| 信息 | 最小内容 |
| --- | --- |
| 目标与完成条件 | 用户要得到什么、本次范围和关键约束；最新纠正覆盖哪些旧结论 |
| 项目与工作位置 | 根卡、当前 KSF 根、实际工程入口；跨设备绝对路径需重新核实 |
| 当前安排 | 正在做哪一步、已完成什么、未完成什么；采用对象的精确 id@version、实际来源和路径 |
| 已确认决定与授权 | 用户原始指令或可信来源入口、允许的动作及目标、适用条件和已消耗动作；记录不自行产生新授权 |
| 产物与证据 | 当前文件、回执、测试结果入口及其实际范围；易变化输入记录版本、摘要或核对方法 |
| 外部动作 | 已完成、未开始或结果未知；已发起动作保存操作 ID、实际回执及下一次对账方式 |
| 待决项与下一步 | 仍缺什么，第一项可执行动作及其前置条件；依赖缺口不阻止哪些独立工作 |

权限、凭据和完整私人资料不复制进检查点。已失效方案从当前安排中移除，必要时保留简短纠正依据和历史入口，不能继续作为下一步执行。


实现接口见 [metadata](../cli/metadata.md)与项目文件工具；程序可读性检查与专业恢复判断分别产生证据。
