# KSF 运行链说明

运行职责由 [runtime](../../abilities/partners/ksf-runtime/partner.md)持有，项目事实方法由 [project-route](../../abilities/competencies/project-route/competency.md)持有，选择顺序由 [ability-route](../../abilities/competencies/ability-route/competency.md)持有。本文解释这些对象的连接，不提供额外运行判断。

正常入口通过context entry完整提供Runtime、人设路由和USER/BOT四项基础内容。能力与项目路由的无前缀精确引用继续核验依赖，正文由Runtime在使用前按需完整取得，复用现有extras及读取确认。人设路由先核对采用已展开的基础卡，必要时补读，详情及维护需求再按明确范围交人设管理。runtime保持目标、任务关系及授权；必要项目事实返回后，能力路由确认承接安排。明确指定、有效原安排及项目预设具有现行方法定义的优先级；全局先协作、再普通搭档，均未命中才进入一次基本功路由，再返回通用处理或具体缺口。

基本功路由搭档通过+引用取得orphan-competency-match，由匹配方法查询有效引用图、核对候选正文与最新资格，交回选择、精确定位及缺口。搭档将实际方法交给Runtime更新安排后，按所选方法执行、核验并返回结果；匹配方法不执行业务或保存绑定。候选、已读、采用和执行是不同事实。程序列举和图解析不执行语义匹配。

六类管理职责分别承接能力、项目、知识、档案、收件箱和人设。专业判断及保存步骤在各领域基本功，确定性操作在程序；没有通用资产维护中枢。跨领域交接通过目标、原件入口、具体请求与实际回执连接。

完整状态与加载逻辑见[Runtime与上下文完整机制](work-context.md)，接口见[context](../cli/context.md)、[task](../cli/task.md)和[route](../cli/route.md)；项目恢复方法见项目推进控制。文档中的图示或示例不创建真实Agent、调度器或额外执行授权。

当前工作绑定与能力参与记录分开。明确指定、有效安排和适用项目预设足以承接时不强制全局发现；进入全局匹配时仍完整读取原始候选描述。每轮由程序计算有效用途、待补正文和退出用途，Runtime 先确认新意图再采用；任务进度及证据仍由专业基本功保存。详见 [工作上下文接口](../cli/context.md#当前工作与增量正文)。
