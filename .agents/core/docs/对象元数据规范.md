# 对象元数据规范

本文件定义四类能力对象的公共契约。公共契约、目录发现、本地精确引用检查和用户接管已由对象 CLI 实现；正文专业质量仍需 Agent 和实际任务验证。通用 `metadata` 管理任意 Markdown，不自动应用本规范。

## 入口与管理单位

对象以承载目录为管理单位，入口 Markdown 使用 YAML frontmatter，后接正文。一个目录只能有一个对应类型的入口；识别入口后，其子目录均作为资源，不再发现嵌套对象。

| 类型标识与 CLI | 系统目录 | 用户目录 | 入口名 |
| --- | --- | --- | --- |
| `cooperation` | `.agents/core/abilities/cooperations/` | `能力/协同/` | `cooperation.md` |
| `partner` | `.agents/core/abilities/partners/` | `能力/搭档/` | `partner.md` |
| `competency` | `.agents/core/abilities/competencies/` | `能力/基本功/` | `competency.md` |
| `data-package` | `.agents/core/abilities/data-packages/` | `能力/数据包/` | `datapackage.md` |

根 `AGENTS.md` 是特殊协同入口，固定留在根目录。新用户对象以完整 ID 作为目录名；已有系统对象目录不重命名。附属资料、模板、程序和 `.upstream/` 快照不成为独立对象。

## 公共字段

| 字段 | 类型与要求 | 含义 |
| --- | --- | --- |
| `id` | 非空字符串，三段格式，类型须与目录一致 | 稳定身份，普通 write 不可修改 |
| `name` | 非空字符串 | 显示名称 |
| `status` | `draft`、`active`、`archived` | 生命周期与接管状态，不是质量验证等级 |
| `description` | 非空字符串 | 作者维护的发现摘要：用途、结果和必要边界 |
| `version` | 非空字符串，精确 `x.y.z` | 对象来源版本，与 KSF 版本、用户修订分别记录 |
| `references` | 可省略或为空列表；精确能力 `id@version` 或显式文件路径，可加单个 `+` / `#` 前缀 | 声明依赖及主文加载方式 |
| `user_revision` | 仅用户对象必需，正安全整数 | 对象服务维护的用户修订号；系统对象禁止携带 |
| `upstream` | 仅用户派生对象的受管映射，包含 id/version | 与当前 ID 和来源版本一致的派生标记；避免丢失基线后被误认成原创 |

可以添加业务字段，但不能改变公共字段含义。程序从 `description` 原样取得摘要，不从正文生成另一套摘要。写入只合并顶层元数据字段，嵌套值整体替换；正文省略时保留。

## 身份与版本

ID 格式为 `类型.命名空间.对象名`，恰好三段，各段非空且不能再包含点号。第一段使用上表类型标识。多词建议用连字符，支持中文；精确匹配区分大小写，不自动转写。

禁止空白、控制字符、`@`、路径分隔符及跨平台非法文件名字符 `<>:"/\|?*`。ID 与显示名称、目录位置分开；命名空间不要求全球注册，`ksf` 命名空间本身不授予系统权限。

版本使用三个十进制非负整数组成的字符串，如 `0.1.0`；每段除 `0` 外不能有前导零，首版不接受范围、预发布标记、构建后缀或 null。日期文本、列表等普通 YAML 值的解析范围见 [metadata](cli/metadata.md)。

系统与用户区各自只允许一个同 ID 定义。同一区重复 ID 冲突，冲突项不作为有效对象；两区同 ID 表示用户接管关系，不构成重复冲突。

## 用户接管与修订

- `draft` 与 `active` 用户对象立即接管；`archived` 保留原目录但退出有效选择，恢复为 draft/active 后重新接管。
- 不限定版本时选择未归档用户对象，其次选择唯一匹配的未归档能力源对象，最后选择未归档系统对象。
- 限定 `id@version` 时先选版本匹配且未归档的用户对象，再选唯一匹配且未归档的能力源对象，最后选版本匹配且未归档的系统对象。两者均不匹配时报错，不自动改用其他版本。
- 显式 `--source system|user` 只查询指定区，可用于检查归档定义；不跨区回退。
- 未归档用户副本损坏时阻断该身份的有效选择，不静默回退。无法识别身份的损坏对象或目录缺口会使相关类型的解析不完整。
- 首次派生保留系统对象的 ID 与 version，默认用户状态为 draft，user_revision 为 1。后续实际正文、元数据或状态变化时修订递增；预览、失败和无变化不递增。
- 用户原创对象也从 user_revision 1 开始，可以显式更新自身 version。派生对象不能通过普通 write 更换来源版本；user_revision 不参与精确版本匹配。

draft 表示仍在修订，不表示“暂不生效”或“候选隔离”。首次派生或修改 draft 后，后续默认读取、发现和依赖解析会立即使用它；从 draft 改成 active 不增加另一层启用门禁，两者均不代表专业效果已验证。需要在采用前讨论的候选保留在当前任务或项目材料中，不能写成同 ID draft 后仍声称系统版保持默认。已有副本需要保留但退出使用时显式归档；对指定系统版的只读检查可用 --source system，不将它作为日常路由绕过用户接管。

固定运行对象：`cooperation.ksf.entry`、`partner.ksf.runtime`，以及 `competency.ksf.ability-route`、`competency.ksf.project-route`，只认指定系统路径，不接受用户派生、接管、删除或身份修改。具体路径见[公共对象命令](cli/objects.md)。用户明确要求开发系统文件时，由宿主工程工具处理已授权差异，不通过日常对象 CLI 绕过保护。

## 依赖与读取

`references` 使用平铺字符串列表，允许能力定位和文件定位：

```yaml
references:
  - "+competency.example.method@0.1.0"
  - "#partner.example.delivery@0.1.0"
  - "+./references/rules.md"
  - "#../shared/context.md"
  - "+/USER.md"
  - "+/BOT.md"
```

能力使用精确 ID@version，沿原有效来源绑定。文件路径必须以 `./`、`../` 或 `/` 开头，不需要能力ID或版本；文件名中的 @ 按字面处理。相对路径以引用所在文件的目录为基准，关联源跟随实际选定的定义目录，不能越出所属源根；以 `/` 开头始终锚定当前 KSF 根，不是操作系统根，也不改为提供者仓库根。使用正斜杠，不接受主机盘符、反斜杠或根外路径。普通CLI对象定位参数仍使用无前缀能力ID，不接受文件路径。

无标记只声明引用；`+` 带出当前能力主文或完整文件后停止；`#` 带出后按目标元数据 references 的各自标记继续处理。普通文件无元数据或无references时结束，文件不必具有能力身份；仅在 `#` 遍历时解释其frontmatter，不扫描正文链接。前缀紧贴ID或路径，重复/混合前缀非法；YAML中 `#` 开头必须加引号，示例统一使用引号。

all/body按声明顺序深度优先展开，父正文及原引用字符串不变。能力项保持 `{reference,object}`；文件项为 `{reference,kind:"file",file:{source,path,source_root?,state,sha256,content}}`。文件content为完整UTF-8原文，包含BOM、换行及原有frontmatter；文件不伪造ID或版本。当前上限1MiB，二进制、无效编码和超限明确报错，不截断；凭据、Git内部及运行目录沿已有工作区文件策略拒绝读取。missing返回null内容和摘要，不创建文件；unavailable表示读取失败并伴随错误。missing是定位结果，业务是否可缺失由采用方法判断；complete不能代替逐项状态核对。

元数据读取、list和check不展开文件内容；check核对文件定位语法和根边界。能力按原来源、ID、版本及摘要去重，文件按来源、规范化实际路径及摘要去重；主文是否已返回与内部引用是否已遍历分别记录，先 `+` 后 `#` 仍可升级遍历，循环停止重复处理。失败保留已取得内容及错误；已读、采用与执行保持分开。

加载标记不改变能力依赖关系。文件定位不会因文件含有id而成为能力身份，也不通过文件内容建立静态搭档关联或隐含导出能力依赖；游离筛选仍沿正式能力ID引用。未显式标记的资源、正文链接、模板、脚本不自动读取，读取脚本也不执行脚本。

导出保留前缀；KSF根路径只保留声明，不读取、自动复制或发布当前实例原文。对象自身资源按既有目录打包；相对文件引用随明确选中的贡献对象重定位，目录外未选资源拒绝导出。显式选中的能力版本映射同步更新入口和资源元数据的能力引用，不改文件名中的@。个人派生保留内部资源相对关系，外部相对文件引用重算后仍指向原文件。资源内容的维护与采用规则归相应能力，文件引用本身不授予写入权。

删除、归档或更改版本之前，检查原本可解析的声明引用是否仍可解析。存在匹配系统版本则允许回退；否则停止发布。首版只做本地精确引用，不做远程获取、自动合并、多版本共存、范围求解或前端升级。

## 对象持久设置与必要状态

四类对象共享[对象 user-data 机制](cli/user-data.md#能力对象配置与必要状态)，无需增加公共元数据字段或逐个声明配置。数据属于当前用户实例，按精确 ID 保存，来源、版本、目录变化不另起空间；不进入对象目录、附件、能力源分享或 .upstream 基线。归档、删除和解除关联均保留数据，显式清除另行执行；更换 ID 不自动迁移。

实际采用或恢复对象时，当前 Agent 按公共运行约定读取持久数据；发现、审阅和普通对象 read 不注入个人值。本次指令优先于存储值，再使用对象默认约定；各对象独立，配置不改变身份解析、固定保护或操作权限。缺失、读取失败和内容不适用应分开判断，具体语义见[系统级用户数据](system/user-data.md#能力对象的持久数据)。

## 完整目录与来源基线

派生复制整个承载目录。用户工作副本中的内部资源关系保持；指向目录外的相对 Markdown 链接按新位置重算，仍指向原资源。系统目录、用户工作目录、系统基线分别维护，系统升级不会自动覆盖用户内容。

用户副本内 `.upstream/snapshot/` 保存派生时系统目录的原始完整快照；`.upstream/origin.json` 记录 `id`、`version`、`ksf_version`、`sourcePath`、文件路径及 SHA256、目录列表和整体摘要。该目录属于可备份、可迁移的用户资产，不放入临时运行数据。check 与更新检查基线完整性；普通 write 不改基线，也不允许调用者设置 upstream。派生标记与基线目录必须同时存在；丢失或不一致时 check/update 报错。

原始快照不能作为运行候选，资源需按需读取。资源自动监控及独立资源编辑命令尚未实现；user_revision 只记录对象 CLI 完成的实际变更。手动绕过服务编辑入口可能破坏契约，不等于对象服务已完成修订或依赖检查。

## 示例与迁移

```yaml
---
id: partner.yinchao.research
name: 研究搭档
status: draft
description: 澄清研究问题、组织证据并交付可追溯结论。
version: 0.1.0
user_revision: 1
references: []
---
```

当前固定入口及runtime的精确身份与版本以根AGENTS和实际对象读取为准，旧assistant定义退役；能力路由和项目路由保持系统固定保护；资产维护已退役，人设路由通过 Runtime 的 `#` 引用加载且不增加固定保护；独立知识路由已退役；知识组织与整理为 `competency.ksf.knowledge-organize@0.1.5`，同样不纳入。精确依赖以实际 references 为准。新增普通维护搭档和四项维护基本功不纳入固定入口保护。draft 与 active 均参与使用，不意味着独立任务或长期效果已验证。

项目基础命令使用 [project CLI](cli/project.md)，不套用能力对象元数据契约。运行职责与当前边界见[运行说明](runtime/minimal-runtime.md)。

各类型的专业正文契约、扩展字段和远程分发仍可后续演进；本规范不将它们冒充现有程序能力。

## 能力源中的对象

能力源以[协议](sources.md)声明独立身份，使用同一四类入口和三段对象 ID，不要求专属命名空间。源中对象不含 user_revision/upstream 或 .upstream/，版本与历史由源 Git 管理。多个源同 ID 可以存在，有效读取歧义必须选源；源内引用绑定本源/Core。源的根 AGENTS.md 不是协同。
