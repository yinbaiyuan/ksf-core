# KSF 开发与测试规范

本文是本地开发、CI 和发行的唯一现行测试规范。命令参数见 [test 命令](cli/test.md)，覆盖范围以[统一清单](../runtime/testing/catalog.json)和本次回执为准。旧验收记录保留当时事实，不作为当前操作要求。

## 选择验证范围

| 阶段 | 必要动作 | 扩大范围的条件 |
| --- | --- | --- |
| 小步修改 | 精确文件或变更快速验证，检查问题及邻近边界 | 出现新的影响证据；简单文案、样式无需强制新增测试 |
| 功能完成 | 受影响组件、公共契约及必要集成；相关类型检查、构建和界面检查 | 跨组件调用、持久化或原生差异 |
| 提交或 PR 前 | 补齐快速与相关集成证据，核对选测计划中的全量需求 | 风险规则要求全量；不因每次提交机械重跑全量 |
| 交付候选 | 对稳定输入补齐通用一次、Mac/Windows原生必需集合及专项验收 | 缺少匹配的可信证明，或来源、锁、工具链、平台变化 |

默认 `ksf test` 实际执行快速档。全量必须显式使用 `--suite full`；快速结果不能替代全量证明。真实模型、付费请求、GUI、跨设备和长期运行单独验收，记录真实环境和缺口。

测试日志和成功缓存有保留预算，运行开始及收尾执行受管清理；当前运行的回执受保护。测试材料不承担源码备份。历史候选和辅助脚本在任务结束后按[运行数据与源码保留](runtime/runtime-data.md)归位、核验并退役，不逐版本复制完整实例。

```sh
.agents/ksf test --changed --plan --json
.agents/ksf test --changed
.agents/ksf test --component sdk
.agents/ksf test --suite full --component core
.agents/ksf test --suite full --profile shared
.agents/ksf test --suite full --profile native
```

变更计划报告 `requiredFullComponents` 和扩大原因，不暗中把快速升级为全量。存储、迁移、锁、启动器、升级发行、公共协议、依赖工具链和选测机制变化必须补齐相应全量。无法精确映射的第一方变更保守扩大；Git 失败必须修复基准或显式选范围，不能声称没有变更。

## 依赖、构建与隔离

开发命令使用 `ksf hello --json` 返回的随包 Node。首次准备、锁文件改变或环境失效时才安装锁定依赖；测试命令不会安装依赖。Core 集成使用 SDK、web 和 Projects 的开发依赖，各目录分别 `npm ci`（SDK、Projects 使用 `--ignore-scripts`）。缺少依赖会在计划中列出，实际运行返回失败。

前端或应用构建输入变化时构建对应产物；服务端测试要求当前前端产物有效。完成一批系统修改后运行 `ksf build --json` 刷新 Core 清单，再 `ksf runtime verify --json`。发行预演只用于发行相关修改及交付候选，运行 `ksf release build --dry-run --json`；它要求干净源码提交，不通过临时提交或覆盖日常实例绕过。

测试在临时根操作，并负责关闭进程、服务和文件句柄，清理目录。不得写业务数据、重启日常后台、修改受管构建产物来让测试通过。生命周期种子仅用于复制，场景目录和 Git 历史独立，不共享可变目录或可被覆盖的硬链接。清单声明 `fixtures:["distribution"]` 的文件共用本次运行预备的compact/legacy-receipt两个种子，预备进程受取消和时限控制；每个场景仍独立复制，收尾核对含Git对象与权限的种子摘要（构建一次，再派生两种回执）。种子不跨运行缓存，legacyEntry与自定义sourceRoot仍单独构造。预备耗时、消费者数量、原始日志和错误进入回执，预备失败或种子变化阻止完成。运行器为每个文件提供本轮专用临时目录，超时或取消时停止拥有的进程树（包括脱离父进程组的子进程），并清理这些目录。Windows 测试 PATH 同时包含所选归档工具目录，避免找到 tar 却找不到 gzip。

并发预算在同一运行器执行，本地与CI一致。普通文件默认共享，quick最多4文件、full最多2文件，并受可用CPU数限制；真实Core复制、Git历史和归档生命周期组在清单声明 `isolation: "exclusive"`。独占文件开始前等待已启动文件结束，独占期间不启动其他文件，结束后恢复共享容量；取消后不再启动排队文件。跨机器分片仍并行，同一宿主机不把两个重型复制/打包链路叠加。新增重型夹具使用者必须声明独占，不能只在CI环境降低并发。

Windows的Node可执行夹具包含额外PE包装进程。模拟单个CLI时显式使用 `containChildren: true`，在启动Node体之前加入关闭即停止的Job Object，避免只杀包装器后留下占用管道或工作目录的Node体；运行时/启动器夹具保持默认生命周期，允许有意托管的后台服务继续运行。崩溃恢复场景等待协议身份已持久化后再终止服务，PID存在只代表spawn，不代表CLI已经就绪。

## 清单与新增测试

清单schema2记录每个文件的 owner、covers、quick/full、输入、平台、超时、依赖、可缓存性及平台耗时估计，并要求 `verification:{lane,kind,reason,nativeContracts?}`。lane为shared/native；logic必须shared，contract必须native，integration按真实边界审查。shared集成声明依赖的native契约。不能按文件是否导入fs就自动判定纯逻辑。平台字段仍表示允许执行环境，CI义务由lane与平台共同决定。owner 是维护者，covers 是保护的组件；应用可引用 Core 的公共集成覆盖，执行时按文件去重。每个第一方测试恰好登记一次；漏登、重复或失效路径阻断全部计划。独立工程、第三方依赖和已安装应用包不自动扫描。

超时是整个文件的硬上限，不随同文件新增场景自动增加。按独立行为拆分真实初始化、重新克隆、事务恢复、来源提升及升级保护/合并/校验，保持全部断言；每组为首次种子准备留出余量。耗时估计用于分片，注明实测环境或保守估计，不能把测试机的估计冒充托管CI基线。出现接近上限的大组时先检查分组和夹具，不以自动重试或统一加时掩盖。

新增测试先明确能阻止哪种有效行为退化，再登记。异步链路分别等待目标阶段的明确状态或受控屏障，不能用接收方业务完成推断发送方已持久确认。子进程超时与整组超时分别设定；耗时场景拆组并保留故障断言。轻量规则和格式组合放快速档，真实进程、CLI、故障恢复、发行与原生差异放全量专属文件；全量同时包括快速。文件混合昂贵链路时拆分，保留有效断言和仍支持的兼容覆盖。清单中的输入必须包含测试、夹具、实现、相关契约和锁；无法完整确定输入的测试不得缓存。`selectionInputs`登记明确的实现与资源关系，执行指纹继续使用较宽的inputs。Core生成清单与web/dist由构建验证，不进入源码影响选择或源码标识；已声明的执行指纹范围不缩减，跨平台重建产物不会扩大选测或改变冻结计划。当前相对字面量依赖闭包只扩大候选；普通字符串或注释不能使未知自有变更免于组件全量。新依赖未登记时保守扩大，动态目录与SDK子路径扩大到相应边界。测试文件自身变化选择该文件及其native契约；风险规则与跨组件调用不能被此优化绕过。新增公共装置或输入关系必须验证选测、分片和失败传播。

应用 `check` 可独立调用，不先加载打包器。测试目录允许使用宿主测试装置；生产源码仍拒绝私有导入，生产入口闭包和实际构建图均拒绝导入测试代码。直接构建与 CLI 构建采用同一必要检查。warning 仍需人工判断，不等于完整安全证明。

## 结果与复用

回执在忽略目录 `.agents/runtime-data/tests/`，区分实际执行、复用、平台不适用、未执行、失败、超时、取消和输入变化。`complete` 只说明所选范围，不代表整个产品。空变更或平台不适用明确返回不适用；空分片不算独立完整证明。

只有本地快速档显式 `--reuse` 才读取成功缓存。指纹包括实际输入字节、夹具、清单、锁、安装工具链字节、Node 和平台环境。失败、取消及执行期间输入改变不产生当前有效证明；输入无法确定的测试不缓存。缓存不是发行门槛凭据。父进程的 Node 测试选择、预加载、覆盖率等参数不传入子运行器，分片只能通过命令显式指定。CI的 `KSF_TEST_BASE` 只用于外层冻结计划校验，不传进测试子进程，避免独立Git夹具误用外层仓库提交。

原生Web关闭测试把夹具准备和重新启动移出关闭计时，关闭仍有6000毫秒显式拒绝期限；未完成连接、重复关闭及原端口健康检查全部保留。逐阶段记录准备、关闭、重启耗时，文件整体硬上限不变。

失败先复跑失败文件，再验证相关组件；只有新的证据显示影响扩大时才追加范围。不要为了收集更好看的耗时反复跑全部测试。耗时分开记录依赖准备、构建、夹具、Git、打包、断言、清理和队列；平台耗时基线用于分片，不作为删减必要覆盖的理由。

## CI 与发行证明

`check.yml` 按事件先约束PR使用精确影响计划；主线推送、手动full或其他缺少可靠基准的非PR运行使用完整义务；不再只传一个full布尔值丢弃选测文件。`verification.yml` 生成并上传 `verification-plan.json`：含实际源码摘要、清单、运行时、Git共同祖先、变更、每组精确文件和计划摘要。消费端重算计划，基准与当前依赖变化、文件增删、平台或摘要不一致均拒绝。计划阶段执行覆盖基线审计。

shared在macOS ARM64基准宿主只执行一次；Windows x64只运行native契约与必要真实集成。Mac native独立分组，Linux Ubuntu22/24保留其声明的原生开发Core契约，不因此声明完整Linux发行支持。按实际选中的耗时估计生成矩阵，shared/Mac各1组（两组Mac作业）、Windows最多4组；空影响不创建无效测试任务。计划、覆盖汇总及required为纯编排，在Ubuntu24执行；Mac名额用于实际通用和原生验证。每平台准备一次锁定依赖与前端，组内恢复SDK链接；固定required要求可复用验证工作流全部适用作业成功。分支保护仍由仓库配置维持。

运行器通过 `ci.js run-group` 校验冻结计划、真实平台与架构后调用同一测试命令。断言失败、超时、取消、缺依赖、准备失败和启动错误在非零退出前落盘，失败报告与逐文件日志始终上传。执行前后核对完整公开源码，包含未跟踪的自有源码；不以输入集合外的源码变化生成成功证明。

汇总下载所有group报告，在上游成功门禁前生成 `coverage.json`：逐组列出shared/native、平台、缺失、重复、失败与夹具预备耗时。schema2证明要求精确计划中的所有文件、完整且互不重叠的组、真实目标架构、零复用、成功、源码/清单/运行时一致。聚合失败先删除旧证明，诊断仍保存；只有完整full计划且所有适用作业成功才上传suite-proof。PR的部分影响验证即使通过也不生成发行证明。

发行只接受官方core-main成功Verify Core运行、相同最终提交和run attempt的schema2完整义务证明。旧schema1的双平台全量回执不自动视为新策略证明；缺失、不匹配或过期时在发行工作流补跑完整shared/native验证，最终包仍独立验证来源、摘要与冻结交接，不改变发布渠道。

`runtime/testing/coverage-baseline.json` 固定a4c0d4f改造前207文件的1399个静态场景表达式。审计比较可执行AST（含外层场景循环及原断言），保留所有业务与故障恢复场景，并逐场景检查native义务没有迁入shared。5个CI策略场景明确替换为新矩阵/门禁断言；动态循环展开后的实际测试数由运行回执另记。维护基线的变动必须有明确覆盖迁移与审查依据，不能以重录当前清单消除缺失。为真实平台补充状态等待等准备步骤时，amendment保留原场景hash、原断言AST清单、理由与原生平台义务，并固定新场景hash；审计必须确认全部原断言仍存在，不能通过删除断言消除失败。

功能迭代确实改变公开契约时，逐场景登记 `contractUpdate` 的理由、新场景hash和原断言清单；只允许把明确列出的原断言替换为对应的新断言，其余原断言和原生平台义务继续强制保留。新增字段、能力更名或目标种类扩展需要说明实际迁移依据，不能重录整个基线或删除原场景来消除失败。

远端工作流在授权推送后记录真实结果。Mac、Windows及Linux原生执行分别留证；模拟平台、策略测试和历史CI通过不能冒充新代码原生验收。耗时必须区分准备、夹具、测试与排队；调度估计仅用于分组，不代替新的实际性能结果。
