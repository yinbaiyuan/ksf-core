# KSF项目应用

Core 内置的 KSF项目应用，使用框架无关的应用 SDK v1。当前维护源为 `.agents/core/applications/projects/`，随 Core 源码和应用源分发，默认离线安装。沿用 `com.ksf.projects` 身份和原有数据目录；从旧独立包升级不会新建另一套项目数据。

源码从原独立项目应用纳入 Core，原仓库仅保留迁移前工作树及 Git 历史。前端仍是独立应用包，不并入工作台前端；运行包包含全部依赖，不在安装时执行 npm。

## 使用范围

- 项目目录：当前、已归档、全部与名称／说明搜索；分别展示正在加载、加载完成后的空目录与筛选无结果。
- 总览：项目目标、当前阶段、可做事项、承诺与容量、阻塞/待决、验收差距及已验收成果。
- 计划与工作：结构化编辑目标、阶段、事项、依赖和验收；旧检查点仍可按明确状态筛选并阅读原文。
- 聊天：新建 Codex Desktop 原生对话、双端接续、明确补充本轮、停止、普通提问和计划选择。历史仍按 KSF 明确主归属分页查询，并保留原文入口。
- 资料与成果：汇集根卡和前 100 份任务文档中的明确链接，显示引用出处，最多 600 条。

项目内容保持原位。应用不推断任务完成比例或自动生成下一步；用户发起的 Codex 对话由 Desktop 执行，按 KSF 现行授权和运行规则处理。自己的 dataDirectory 只保存显示设置、最近线程及操作编号；Core 不复制完整聊天正文。缺少状态的文档与未知检查点格式显示为未标注，解析失败单独报告。

## 前后端边界

前端独立打包 marked 和 DOMPurify；原文按 Markdown 安全渲染，不执行原文 HTML、脚本或嵌入内容。应用样式全部限定在 `.ksf-projects` 下。SDK 仅用于 RPC、窗口对象信息和销毁；不导入 Core 内部前端组件或依赖宿主 React。

后端通过 SDK 公共 `projects` 服务查询项目及其任务，使用工作区原件读取任务文档，不依赖独立仓库或导入 Core 内部模块。拒绝路径越界和符号链接；文本预览上限 2 MB，项目内容读取不修改文件。设置通过公共存储服务原子发布，多窗口的最后一次设置保存生效。

文档与历史聊天原文入口使用工作台已有 URL，在新标签页打开并保留当前项目位置。接续既有聊天必须经 Core 核验当前 KSF 根、原生 threadId 和历史主归属；无法匹配的保持只读。目录和非文本附件展示路径与引用出处，支持的图片通过工作台媒体接口打开。

后端通过 `@ksf/sdk/codex-conversations` 调用 Core，清单声明 `codex-conversations` 权限。首版需要本机 macOS Codex Desktop；审批统一在 Desktop。派发超时只核对原操作，不能自动重发或切换执行端。页面隐藏或失焦暂停观察；关闭窗口不停止 Desktop 任务。完整契约见 Core 的 `docs/codex-conversations.md`。

## 构建与分发

```sh
npm ci --ignore-scripts
npm test
npm run build
```

使用 Node.js 24。依赖版本由 package-lock.json 固定；构建复用 Core SDK，输出 `.build/` 和同级 `store/` 中的 `com.ksf.projects-<版本>.ksfapp` 及索引。应用依赖的第三方许可证由构建脚本收集，并随包附加到 SDK 许可证说明。

`tests/install.test.mjs` 使用真实应用管理器及隔离实例，验证旧包升级保留设置、资源读取和新实例无网络默认安装。测试不依赖原独立仓库或环境变量开关。

Core 默认应用列表、随附应用源和源代码分发共同包含本应用。现有实例通过既有版本更新机制升级；安装/更新只改变应用包，不移动用户项目或重置偏好。

自动测试使用临时虚构项目，覆盖结构化检查点、缺失／错误记录、路径边界、CLI 参数、归属分页、设置持久化和清理；真实安装与页面验证另存于 ksf-develop 的验收记录。构建与程序测试不替代对应平台的实机安装和页面验收，平台结果以对应发行记录为准。
## 0.3 项目管理闭环

七个视图为总览、目标与阶段、工作事项、风险与决定、原始检查点、资料、项目对话。总览使用显式管理主件展示阶段成果、可做事项、承诺/容量、阻塞/待决和验收缺口；原检查点仍按原文读取。项目未建立主件时不自动接入或写入。

目标、阶段、事项、依赖、风险、决定、验收条件与证据均可结构化编辑；修改先保留窗口草稿，显式保存。后端经公共 projects.managementRead/Check/Write 使用与 Agent CLI 同一服务，不自建应用私有项目库。模型与接口见 [Core 项目管理契约](../../docs/project-management.md)和 [project CLI](../../docs/cli/project.md)。本地开发需要包含这些公共服务的 Core，与本版应用成套使用。

并发修改按读取基线、窗口草稿和最新内容作稳定 ID 三方合并。非重叠修改共同保留，重叠修改逐项选择；保存仍需最新 ifMatch。未知回执优先对账，格式损坏不覆盖。旧检查点显式逐项接入为候选事项，来源状态独立保存，不自动同步或冒充当前验收。

准备推进对话只生成可核对的交接草稿，填入现有项目对话后再发送，不自动启动模型或改变事项状态。应用没有新增自动排程、后台重试或周期汇报。

开发迭代可用 `KSF_PROJECTS_BUILD_STORE=<隔离输出目录> node build.mjs` 验证候选包；默认构建才写随包应用源，同版本内容保持不可变。`tests/preview-server.mjs` 只在临时虚构项目上验收界面，不打入生产包。

## Markdown项目治理

0.4.1按根卡governance_schema分流：旧项目保留原计划界面，新项目沿公共projects.governanceRead/Check/Apply读取和维护项目、里程碑、任务、编号上下文及两级复盘。窗口保留草稿和未知保存操作，冲突按原件三方合并。业务数据只写Markdown；新格式错误不回退旧JSON。详见[治理协议](../../docs/project-management/governance.md)。

隔离界面验收可设置KSF_PROJECTS_PREVIEW_GOVERNANCE=1与KSF_PROJECTS_PREVIEW_PORT启动tests/preview-server.mjs，不操作真实项目或发送Desktop消息。

## 结构与灵感

总览用里程碑路线显示当前重点和任务完成比例；目标与阶段支持层级结构与安排列表，展示递归父子项目、里程碑及任务。节点详情单独说明前置依赖和所属关系。完成比例不代替阶段验收。

每个里程碑可直接打开灵感闪现，按需读取、原样保存。窗口草稿、源文件摘要和操作ID保护并发修改；重叠文字明确展示双方，人工选择后再保存。手记不会自动生成任务。

项目、里程碑和任务详情统一使用就地文件工作区：左侧浏览当前对象目录中的文件和普通子目录，右侧显示正文或专用编辑页。下级对象从左侧对象导航进入，不混入当前文件树。普通 Markdown 共用即时预览、源码、分栏、阅读、大纲和自动保存，外部新增、修改与删除沿用会话审阅提示。对象详情、复盘、灵感及推进入口集中到顶部；任务的验收继续在任务详情中维护。配套 Core 通过 `objectPath` 核验对象身份和目录范围，旧 Core 保留原编号上下文浏览。

项目方案按「方案、推进、资料与成果」分区，同一份草稿随分区切换保留。方案聚合基本信息、父子项目、管理参数、目标、完成条件和原有方案正文；推进聚合状态、管理阶段、下一步、重点里程碑、风险和决定；资料与成果支持按名称、来源和路径查找项目资料及成果证据。各组默认阅读，按组进入编辑，继续使用标题行的保存与并发合并。上级项目变更通过公共 `setParent` 原子更新双向关联。固定版本证据按摘要只读打开，支持图片预览与原件下载，不回退为最新正文。

0.10.86 将方案改为目标和方案正文优先的阅读界面，管理参数在基本信息中按需展开；推进分别显示人工关注、实际在制、下一批承诺及公共可开始判断。任务完成参考与里程碑有效验收分别显示，数量不当作目标达成率。成果按文件合并当前与固定版本入口，同时保留每项引用的来源、目标、条件、复核者、时间、原始结论及需复核状态；复盘的草稿/完成状态与通过/未通过结论分开展示。“收起编辑”只结束输入态，实际保存仍由标题行明确反馈。

项目记录与程序统计、Agent 分析简报使用独立阅读区。简报通过工作台已有受管 `ai` 服务手动生成，读取已保存治理原件与限量项目上下文，不含窗口草稿，不自动改写承诺、重点或验收。应用私有 `project-briefs.json` 只保留每个项目最近成功报告与最近运行，显示生成时间、覆盖范围、依据版本及待更新状态；来源变化时不把旧分析冒充最新结论，失败保留上一份报告。Agent 不可用时正式记录及编辑继续可用。本期不创建定时任务，也不自动采纳分析为正式项目记录。

0.10.87 按用户反馈恢复默认可见的基本信息：项目名称、状态、当前管理阶段、负责人、规模、类型、在制上限和父子项目集中紧凑展示，直接进入分组编辑。状态与阶段在方案和推进中共用同一份草稿；暂停与阻塞继续要求必要原因、下一步和恢复条件。三个分区统一收紧留白与列表间距。Agent 简报的页面、占位及前端读取/轮询撤下，已有应用私有缓存不删除，不自动请求分析服务。

0.5.0使用公共治理stateModel取得六个主状态，受阻为独立标记、可开始为公共派生判断；schema2可编辑，schema1只读保留并由Agent显式迁移。界面保留草稿和条件提交。业务定义不依赖core/docs，正式模板在项目推进搭档能力包。

项目级归档与恢复（0.6.0）：通过公共projects.archive/restore预览并条件提交显式批次，保留六主状态、关联、证据及原始材料；恢复不自动启动任务。当前窗口和批次内已保留的草稿须先处理，未知操作回执按同一请求对账。归档显示范围与业务状态、只读浏览及恢复入口。缺少配套Core或旧格式时保留原件并提示能力缺口，不自行移动目录。正式流程定义见验收能力原件，docs只用于解释。
