# KSF 工作台前端

React + TypeScript + Vite + Tailwind CSS。`src/components/ui/` 使用 shadcn/ui 的源码组件方式，在 Radix primitives 上定制按钮与 Sheet；图标使用 Lucide。组件随源码维护，不依赖远程组件服务。Markdown 使用 react-markdown / remark-gfm / rehype-sanitize，不解释原始 HTML，不加载远程图片。

## 开发与构建

在此目录执行 `npm ci`，然后 `npm run typecheck`、`npm test`、`npm run build`。依赖版本固定在 package.json 和 package-lock.json。构建必须使用 KSF 已安装的随包 Node：将 `ksf hello --json` 的 `runtime.nodePath` 所在目录放到开发命令 PATH 最前，npm 可使用开发机已有安装。发行用户不需要 npm。

`npm run dev` 仅供开发，监听本机并将 `/api` 代理到 127.0.0.1:4173 的现有 KSF 服务。日常使用从 KSF 根运行 `.agents/ksf web`，它只提供 `dist/` 中校验过的预构建资源。

`npm run build` 执行类型检查、Vite 生产构建、运行依赖许可整理，并生成 `dist/build.json`：源码/锁文件摘要与构建资源的逐文件 SHA256。构建不依赖用户的项目、对话或个人信息。输出的 `dist/THIRD_PARTY_NOTICES.txt` 随包保留。Vite 清单用于收集所有入口、分块和样式，不把 dist 整个目录开放为静态目录。

Core 的 `.agents/ksf build --json` 以及 Web 启动核对构建新鲜度与资源校验和；失败时提示前端重建，不自动联网安装。开发依赖、Vite 缓存、覆盖率、测试输出及界面验收截图从系统摘要、贡献和发行中排除。源码、锁文件与 `dist` 都属于正式 Core 资产。

## 行为约定

- 地址通过 target、task、原生 turn（旧 project 映射兼容） 保存选择，section=request/route/result 保存章节定位；旧 tab=conversation 定位请求，tab=route/routes 定位路由，旧版入口保留 view=routes 与 session。
- 归属目录来自全部历史事件的主归属，分项目、知识、能力、档案四组，标题不增加导航层级。聊天只出现在曾明确作为主归属的对象下；关联对象不收录聊天。默认打开最近以当前对象为主归属的轮次，不复制原件；知识按精确入口路径区分。
- 轮次栏保留完整聊天上下文并分页，标出本项目、本知识单元、仅关联、其他归属、无归属、待确定、未上报、未记录；轮内主归属切换显示顺序及最终归属。
- 本轮同页按请求、路由、结果三段展示。用户原话约八行预览，可展开全文；复制与原文始终使用完整内容。路由使用默认展开的纵向演进线，首节点完整呈现主归属、关联项目／知识和四类能力，后续节点显示前后差异；节点及来源详情绑定当时事件。最终答复默认展开，过程说明、交互问题、用户选择与其他可见回复统一折叠并保持原始顺序。每条消息只进入一个分区，未知阶段不丢弃，缺少最终答复不根据完成状态补造。固定入口不展示，原始记录保留。
- 路由演进按档案顺序计算，仅主归属、关联对象、能力选择/读取/采用、增减与精确定义差异产生节点；同次多项变化为一个节点，跳过的能力阶段不补造。排列顺序、固定入口、来源查询装饰、摘要、说明及 Agent 处理状态不产生节点。原始上报与 Agent 状态从记录信息进入，主路由不显示上报次数或状态更新分组。
- 新轮次与新路由在一个更新区域提供准确跳转；新路由提示比较实质安排，纯状态上报不触发提示。正常主归属不重复提醒，仅关联、其他归属关系在路由区标注，归属切换沿演进线呈现。读取错误及采集缺口集中在记录信息，其入口提示数量。
- 可见页面每 3 秒刷新；隐藏时不发新查询。取消已离开的查询，失败保留上次成功数据；分页按 ID 去重。历史轮次、展开状态、滚动和抽屉不随轮询重置。
- React 负责文本转义，Markdown 另行清洗。只允许显式 http/https 链接，原始附件及本地引用显示为文本。Radix Sheet 的遮罩不启用会注入内联 style 标签的滚动锁，保留生产 CSP。

## 验证

后端使用 KSF 随包 Node 的 node:test。前端 `npm test` 验证消息分区与去重、原件不变、多最终答复、未知阶段、章节及旧链接定位、默认轮次、路由差异与链接处理；浏览器覆盖 1440/1280/787/390、长请求、缺失与排除状态、抽屉焦点、刷新保持以及 Markdown 注入。验收示例始终在临时根创建并标明，真实工作区不插入演示任务。

## 归属与聊天导航

主工作台采用项目／知识／能力／档案分组的归属聊天树、完整轮次栏、同页证据阅读。`/api/task-targets` 只聚合历史主归属，没有归属记录的知识单元不预铺菜单。虚拟入口区分无归属、待确定、未上报、未记录。计数、默认轮次与最近上报使用 targetContext，不复用聊天整体 latestReported 冒充归属事实。

接口：/api/task-targets；/api/tasks?target=...；/api/tasks/:taskId?target=...；轮次正文按需加载。旧 /api/task-projects 和 project 查询继续兼容。URL target/task/turn 可刷新与前进后退，旧 project 链接解析后保留轮次。查询不写历史原件，来源不可用不自动改绑，只讨论知识不自动编辑正文。

待创建目标以稳定 targetId 聚合，目标落成前显示“待创建”；绑定后主身份不变，演进投影新增目标建立事件，不伪造成主归属切换。目标详情与采用能力分开，技术信息显示身份版本和精确定位。历史目标使用当时快照，currentBinding 只作后续信息；目录生命周期可显示当前绑定状态。绑定别名用于兼容没有独立旧历史的物理键，旧项目链接保留指定轮次。
