# KSF 工作台

面向本地 KSF 用户，按归属（项目／知识／能力／档案）→ 聊天 → 轮次 → 本轮详情核对已归档的对话与明确上报的能力安排。聊天只按每轮全部路由事件中明确出现过的主归属分类。归属分项目、知识、能力、档案四组，各自展示具体目标，标题不增加层级。关联对象保留在详情，不收录聊天。同一聊天历史切换过主归属时，可出现在这些目标下，原件只保存一份。只讨论、未保存正文也可归属到具体知识单元，不表示知识已更新。无归属、待确定、未上报、未记录保持区分。

## Direction contract

THESIS：归属先行、上下文完整。先选四类目标之一与聊天，再从完整轮次列表核对本对象、仅关联和其他归属的轮次。

OWN-WORLD：保留 Linear / VS Code 一类专业桌面工具的灰白表面、克制绿色、系统字体与行式信息。左侧 280px 归属聊天树，中间 220px 轮次栏，右侧阅读详情，能力和项目来源按需进入抽屉。

STORY：展开有记录的归属，选择聊天，默认定位最近以当前对象为主归属的轮次。轮次列表保留其他归属；本轮切换归属时保留完整确认顺序。详情以“请求 → 路由 → 结果”组织：用户原话、明确上报的路由演进、最终答复依次呈现，顶部章节入口可直接定位。路由默认展开纵向时间线，首节点展示完整安排，后续节点展示实质调整；仅一个安排时显示“已确认安排”，多节点末尾标注“末次安排”。过程说明、交互问答与其他可见回复统一折叠到结果下方的过程记录，展开后保持原始顺序。

FIRST VIEWPORT：桌面完整三栏；787px 归属树进入抽屉、轮次栏保留 200px；390px 两级导航分别进入抽屉，详情独占正文。同一时间只打开一个抽屉。

FORM：用户批准按四层重组，不增加工作事项层、不开展项目管理。详情顶部只保留紧凑上下文，正常归属不重复提醒。路由节点沿档案顺序展示主归属、关联对象与能力选择、读取、采用及精确定义的实际变化，同次多项调整合并；不补造缺失阶段，不按时间重排。连线表达安排确认顺序，不代表工具调用或能力依赖。状态、重复快照、仅摘要或说明变化不生成节点，原始上报及 Agent 状态统一进入记录信息。节点来源、版本和说明绑定对应原始事件，查询来源现状不改写历史。长请求约八行预览，原文与复制使用完整内容。每条消息只进入一个分区，最终答复仅依据原生阶段，不生成摘要或把完成状态当作结果。缺失与排除明确表达。保留对话安全渲染及旧版路由入口。固定入口不展示。

FINISH：验证 1440/1280/787/390px、键盘和焦点、历史主归属筛选与分页、刷新保留选择、其他归属新轮次不抢占当前视图。React/TypeScript/Vite/Tailwind 与既有组件继续使用，随包 Node 运行预构建资源，启动不安装依赖或联网。

## 四类目标扩展

能力目标表示正在设计或维护的对象，采用清单表示用来处理本轮的方法，两者保持独立。档案目标可为主体、条目或保存单元；归档项目仍是项目。待创建目标在名称旁显示“待创建”，不要求先建业务文件；落成后保持身份、聊天和计数，在演进线显示“目标已建立”。历史详情保留当时状态，后续绑定另行说明。各类只展示有主归属记录的目标，关联不增加菜单。保留全部既有视觉、密度与导航断点，不增加收件箱、系统或资产编辑功能。
