# 能力维护

## 职责与结果

对协同、搭档、基本功和数据包执行具体维护：确认有效对象、分析变化影响、选择真实操作路线、条件写入并读回核对。返回无需变更、建议或实际维护结果。

整体对象组合由能力管理确定，专业定义交相应设计方法，内容工艺问题交能力诊断。本方法不重新设计专业算法，也不承担项目、知识等其他管理责任。

## 1. 确认对象与变更基线

取得维护目的、允许范围和待落实差异。用对应类型 list/read/check 核对精确 ID、版本、实际来源、状态、目录、资源和引用；同名不代表同源，坏副本不静默回退。

读最新原件并保存可比较基线。先判断是原位修订、个人派生、资源/配置调整、归档还是物理删除。普通个人定制优先复用或派生；明确 Core 开发才使用当前工程修改系统源。

退出：对象、来源、允许动作和基线明确。只要求审查时交影响和方案，到此不写入。

## 2. 分析实际影响

沿现有解析规则检查直接和间接引用、文件资源、固定入口、项目预设及当前工作绑定。加载标记不改变依赖；不能用字符串截断规则忽略文件引用、来源或版本。

生命周期和身份变化还须核对个人设置、聊天状态、派生基线及关联来源。对象退出不连带清除其设置、变量、参与历史和项目证据；只更新当前有效引用，不改写历史原文。

依赖尚未处理时不删除原件。需要替代对象时先形成可读候选及具体换接差异，不能事后以“旧对象不存在”说明迁移完成。

退出：受影响位置及保留内容明确，当前依赖能够通过替代、换接或明确保留继续闭合。

## 3. 选择并执行操作

普通用户对象优先使用已有原生 write/remove 及 dry-run，写入带最新版本条件。Core 开发使用宿主工程工具，只改授权目标，写前比较最新原件；有并发变化先合并，不能覆盖整份旧快照。

派生保留真实上游版本、资源及基线，不把个人修订伪装成上游原件。对象个人值按完整 ID read 后用 etag write/remove，临时参数不自动持久化。

改名先检查实际可用迁移支持。现有 ability-manager migrate 只处理既定 object-designer 到 ability-manager 的身份迁移，不是任意 ID 改名工具。其他改名逐项处理当前引用及确实存在的数据；能力不足就保留冲突和待办，不编造通用映射或重写历史。新正式身份不自动继承旧身份的历史计数。

归档和删除按实际接口区分；资源操作保留所需原件。多文件记录逐项结果，失败只撤回能识别且没有后续改动的本次差异，未知重叠保留现场。不声称跨文件原子事务，不盲目重做结果未知的操作。

退出：实际写入范围与授权一致，每项结果可核对，必要失败及剩余条件已保留。

## 4. 读回与交付

重读定义、资源和受影响入口，核对元数据、版本、精确引用、来源、资源路径及实际正文差异。Core 变更执行相关回归、文档/资源检查和构建；验证范围必须对应变更影响。

交付实际对象与来源、完成差异、影响处理、检查证据、保留数据和未决。没有变化不重复写入。源仓库 Git、对外分发与发布按相应维护职责及具体授权处理。

## 案例与结束

删除仍被搭档引用的方法：先准备并核对替代或移除配置的具体差异，再删除，最后重读依赖。若写前出现他人新改动，保留并比较，不以本次基线覆盖。

边界：修改方法如何判断不属于机械维护，交专业设计；只移动资源或刷新精确版本可在本方法完成。数据包内容的专业加工仍交领域方法。

当本次维护结果和当前影响已读回、必要记录及交接完成、剩余条件明确时结束。本方法没有独立持久字段，不保存第二份资产总表。
