# 能力维护

## 输入与结果

输入为具体对象、维护目的、允许范围、当前定义与可取得来源。输出是无需变更、具体建议或实际维护结果，包含有效身份/来源、差异、引用影响、检查及未决。仅阅读、评审不产生保存或采用。四类对象均适用；数据包内容的专业处理仍需适用领域方法。

## 判断与执行

1. 用对应类型 list/read/check 核对精确 ID、版本、来源、状态、目录、资源和直接引用。普通个人定制优先复用或派生，不把同名当同一来源；来源歧义先明确来源，坏副本不静默回退。
2. 内容有同一独立结果时优先完善；确有独立责任、方法或分工才转三项设计基本功。生命周期、资源和配置维护在本项完成，不为机械操作另造基本功。
3. 写前重读并保存可比较的基线，检查直接及间接引用者与当前项目预设。用户明确归档/删除时先展示实际影响，再用对应对象 write/remove 的 dry-run 和实际操作；归档不等于物理删除，依赖断裂未处理不能声称迁移完成。
4. 普通对象使用原生条件写入接口，保持系统/用户/能力源及派生原版边界。明确系统开发使用宿主工程工具，随后检查对象及构建。源仓库 Git、导出与发行交维护搭档，不能由本项隐式公开。
5. ID 改名必须同时审查现行引用、预设、用户设置和聊天状态。使用 `ability-manager migrate` 先预览再 apply 迁移既定旧身份；冲突保留双方，历史原文保留旧身份并通过读取映射解释。派生基线不得伪造为改名后的上游原件。
6. 对象个人值按本对象完整 ID read，使用最新 etag write/remove；临时指令不自动保存。对象退出不连带清除设置、变量或历史。
7. 写后重读定义与受影响入口，核对元数据、精确引用、资源路径及正文差异。多文件逐项记录，失败只撤回可识别且没有后续修改的本次补丁，未知重叠保留现场；不声称跨文件原子事务。

## 交付与案例

交付对象、实际来源、维护差异、完成项、检查和剩余条件。引用刷新只改当前有效入口，不改写原始聊天或历史回执。

示例：删除一项仍被搭档引用的基本功，先形成替代或移除该配置的具体差异；未解决依赖前保留原件。反例：删除后以“对象已不存在”宣称维护完成。边界：仅要求建议时返回影响与方案，零写入。本项无独立持久字段。
