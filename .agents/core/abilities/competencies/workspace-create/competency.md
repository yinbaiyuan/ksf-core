# 创建用户实例

## 输入与结果

输入是 Core 来源、目标绝对路径、文件夹或私有仓库方式及用户授权。结果为独立命名、准确记录 Core SHA、可进入孵化或工作的个人实例。升级已有实例、资料导入和正式发布是独立任务。

## 方法

1. 核对唯一官方 Core、平台、版本与来源；正式包须与可信索引的尺寸和摘要一致。development 包只能明确用于本地试验，不冒称正式来源，不能把维护者个人实例复制给别人。
2. 核对目标及父目录，目标必须不存在或为空；非空或链接冲突保留现场。名称可为 ksf 或自定义名称，不因此改变系统身份。不得自行删除旧目录。
3. 仓库方式从 Core 默认 core-main 使用模板建立自己的 Private 仓库，只包含默认分支，再克隆目标。模板产生独立历史。远程创建和推送须在本次授权范围内，不能把公开 fork 当私人资料空间。
4. 文件夹方式下载并校验 Core 包，用受限归档实现解到空目录，保留隐藏文件与启动器权限；或复制已验证本地构建的 ksf/ 检查目录。普通文件夹不要求 Git、全局 Node 或包管理器。
5. 使用该实例固定入口执行 `instance init --json`，核对返回结果；原始模板通过初始完整树匹配 Core SHA。命令只补齐缺少的通用用户文件，保留已有个人内容；从当前 HEAD 新建并切换到个人 main，保留原本地和远端 core-main；设置本仓库 main 跟踪和默认推送到 origin/main，不继承 core-main 的跟踪关系。显式 origin push 映射、mirror 配置及不满足恢复条件的另一条 main 保留冲突。不提交、推送、更换远端 URL 或修改远端默认分支。来源未核实、系统已改动或分支冲突时保留错误，不手写回执。更旧来源可在核实后指定完整 revision，仍须匹配初始树。
6. 再取 `context entry --json`，完整遵循孵化或 runtime 要求，保留原始任务。核对运行时、系统定义与能力发现。启动本身不查新版或联网升级。
7. 若需要个人远端备份，按明确授权正常推送自己的 main，核对远端 main 更新且 core-main 未变；远端默认分支可以继续为 core-main，不把个人历史送往 Core。仅本地创建不自动创建远端。创建失败只清理本次能确认归属的临时文件。

## 交付与验收

已有个人实例再次克隆时，默认分支可能仍为初始 core-main。使用实例 init 恢复已有本地 main 或 origin/main，核对 resumed、准确提交和用户文件；须有有效安装凭据、属于当前快照的后继且无已跟踪修改。恢复不联网升级、不重新孵化、不覆盖普通或忽略文件。存在 main 但不满足恢复条件时保留冲突，不创建另一条初始分支。官方源的常见 HTTPS、SCP、SSH 写法及 origin 实际推送到官方 Core 均受保护。旧入口尚无恢复功能时，在新目录显式 clone --branch main 取得已有实例。

交付实例绝对路径、创建方式、来源版本与 SHA、本地和远程分支实际状态、用户内容保护、程序调用证据和未决项。程序入口通过不代表新 Agent 会话已真实采用定义，两者分别记录。

正例：从 Core 模板创建独立私有实例，验证后进入 main 和孵化。反例：复制已有个人 KSF，或把分支名当来源校验。边界例：目标非空、旧模板查找不到、已有 main 均保留实际冲突。

协议见[发行说明](../../../docs/distribution.md)及[实例初始化](../../../docs/cli/instance.md)。

## 首次上下文验收

正常模式核对 context.complete 及 USER/BOT、runtime、两项路由的来源与全文；初始化/孵化模式遵循其当前入口。缺失用户内容与读取失败分别保留，不用旧实例资料填补。交付能继续首项工作的入口及未决；已创建目标不重复初始化。本项无额外持久字段。
