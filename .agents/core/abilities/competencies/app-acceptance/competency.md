# KSF 应用验收

## 使用与标准

输入为本次目标、改变的实现、候选包/摘要、目标 SDK/宿主/平台、已有可复用证明和安装授权。输出与这些输入对应的验收记录、必要交付物、阻断项及未验证范围。记录模板见 [验收记录](templates/acceptance.md)。

从用户可完成的业务闭环和 KSF 接入契约建立标准，不用页面好看、文件存在、构建成功或测试数量代替结果。按需读取 SDK 类型、错误、所选能力的技术说明；规范要求由本方法持有，确定性字段与接口由实际程序校验。

## 选取并执行

1. **固定输入。** 记录代码/锁文件、SDK、宿主、平台及包摘要，复用与当前输入相符的已有证据。源码或候选变化只补受影响的检查；不以当前重跑覆盖历史失败。
2. **按改变的实现选测。** 执行工程现行规范和选测计划要求的检查。纯应用改动验证应用与消费的公共契约；仅消费 SDK 或调整文案样式不等于修改 SDK/Core，不机械跑 Core 全量。若实际修改 SDK、宿主、持久化或公共协议实现，则补齐所属组件规定的回归，由相应责任承接其系统交付。简单可逆样式不新增镜像实现的测试，业务数据/并发/恢复变化必须有有意义的验证。
3. **程序与包检查。** 运行必要的类型、SDK check、应用测试及构建；检查入口、静态依赖、资源、许可和目标平台/ABI。error 阻断对应交付，warning 有实际复核结论。包能解码不等于能完成用户任务。
4. **临时实例验收。** 需要运行/升级时取得元数据引用的安装基本功，使用虚构业务数据和隔离实例安装固定候选；运行目标主路径及受影响的失败、并发、关闭/刷新/重开、草稿、数据损坏或迁移场景。业务原件不作为破坏性夹具，不为测试改真实用户文件。
5. **对应能力专项。** 窗口检查控制条默认不重复显示应用名、控制按钮/拖动可用及无障碍窗口识别，明确表达的业务对象标题与工具栏不受影响；并核对实际任务、最小尺寸/窄窗、焦点/快捷键、保存关闭和资源清理；卡片检查配置独立与宿主拖缩不被拦截；数据检查冲突、失败、回执未知、兼容与恢复；AI/通信/后台/CLI只对声明且本次要求的能力验证。模拟模型、合成输入与真实供应商/中文输入法/原生平台证据分开，不默认付费调用。
6. **本机与公开交付分别核对。** 当前 KSF 安装在授权范围内且必要验收已达标时，按安装基本功接入并核对原数据。公开源交付还需由发布基本功组织真实索引、包、素材回读与干净消费者安装；本机缓存中的成功不能替代公共源可安装。

## 判定、交付和结束

每项标明通过、失败、未执行或不适用，并附输入和证据。必要业务/安全切换/数据检查未通过不报告对应交付就绪；缺环境不能写成通过。确实不属于当前应用目标的系统失败单列范围与原因，仍保留原始失败，不能把整体报告改成全绿。公开或跨平台声明必须有对应证明。

交付按范围包含包及摘要、源码/SDK引用和锁文件、配置与使用说明、实际验收/安装记录、数据迁移及代码回退限制。没有真实执行的只列计划；证据已足够后结束，不为凑记录反复跑全量。工具和真实使用均未验证的新方法只能报告情境走查，不声称独立模型或长期效果。
