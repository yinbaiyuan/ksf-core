# 改进落实与效果复核

## 结果与边界

独立结果为一次可追溯的改进处理：建议身份与来源、人的决定、唯一目标与版本、实际差异、落实结果及证据、验证范围、后续效果和未决。用于飞轮建议或明确用户纠正的后续处理；纯证据回顾不进入此项，建议存在或读取不产生写入授权。

输入为具体问题、来源、拟改目标、变化理由、建议差异、预期作用和验证办法，以及本次明确决定与授权。缺目标先形成候选并核实，不按名称自动改绑；来源缺失保留限制。明确修订要求已经授权时直接实施，不再设置重复审批。

## 处理方法

1. **核实是否同一问题。** 比较现有建议的稳定身份、目标、来源和实质变化，复用已有项。拒绝/暂缓项无新证据不重新生成；新来源补证据而非复制一条同义建议。问题已解决时核查当前原件与结果，不重新执行。
2. **确定目标和差异。** 读取当前目标及其规则，辨别项目当前工作、知识认识、可复用方法或通用质量问题。事实不自动转成能力；确有可复用过程、判断、纠错与可检查结果时才建议能力设计。优先完善现有正文，保留来源、适用条件和不确定性。
3. **落实处理决定。** 采纳只表示要处理；记录待落实或执行中及范围。明确拒绝保留理由，暂缓保留恢复触发。执行前核对当前基线及有效授权；版本已变比较后合并，不以旧草稿覆盖。价值取舍或授权实质扩大只处理新增未决部分。
4. **交接专业处理。** 交接建议 ID、来源路径/轮次、目标身份/版本、具体差异、允许范围、验证办法和返回要求。知识按实例组织方法，能力按对象设计与验证，项目按其三项基本功；档案、人设和收件箱分别交相应管理职责；各领域方法落实写入与检查，不复制另一套定义或当前业务事实。
5. **核实实际落实。** 读回目标、核对修改和原件入口，记录实际动作、落实者、时间、结果证据和未决。结果未知先按原操作身份对账，不能因“已采纳”或 Agent 回答“完成”关闭。应用能记录落实结果，不等于程序独立证明其语义正确。
6. **分开验证与效果。** 结构/引用、程序检查、当前使用、独立会话与长期效果分别说明。观察后续项目是否实际采用该版本、原问题是否复发或返工减少；没有后续样本明确尚未观察。验证失败继续返修或撤回本次差异，保留历史问题与失败证据，不美化为成功。

## 数据与支持

飞轮继续持有报告、建议、人的处理决定及落实/复核记录；项目、能力和知识各持有唯一现行原件。只保存必要身份、入口、版本和结果，不复制正文，不建立跨四域的万能事实库。应用私有 SQLite 两库按现有恢复协议保留，不把执行恢复库当可丢缓存。

当前能力/知识应用可准备处理草稿，飞轮可跟踪建议及落实记录；草稿与跳转不启动 Agent、不自动发送。真实执行由当前宿主和已授权专业安排完成，回执或读取对账成功后才称为已保存。对象 user-data 无独立持久设置，处理过程留在相应业务记录。

## 质量与验证

模拟正例：用户采纳“项目恢复要先读管理主件”，差异写入唯一推进方法，引用更新并通过恢复场景，后续任务再观察效果。反例：三个应用各复制一份待办并按最后修改时间互相覆盖。边界例：无新证据的已忽略建议不再提醒，仍保留历史可调阅。

验收可从落实记录回到原建议和当前目标，采纳与写入分开，验证结论不越级。覆盖目标缺失、版本变化、重复建议、拒绝/暂缓、写入失败/结果未知、未实际采用和效果未改善；程序契约、实际使用与长期成效分别报告。
