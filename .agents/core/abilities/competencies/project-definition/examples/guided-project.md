# 项目定方案完整交互样例

以下为构造样例，不是真实用户效果或已执行回执。

用户：帮我做一次内部分享。
Agent：我先确认分享要解决的事情。现有材料显示大家会使用工具，但不会判断适用场景。我建议以“参加者能独立选择一个真实场景并完成练习”为目标；另一个方向是仅介绍功能。你希望哪一种？
用户：前一种，控制在一小时。
Agent：采用实践目标和一小时约束。完成条件建议是有一套可实际授课的材料和练习，且经过一次试讲；参与者的真实表现待活动后核对。是否还需要组织报名？
用户：不用。
Agent：范围据此收敛。建议A档，先做小样试讲再完善。已有目标直接采用；将上述条件与边界保存到project.md，下一步拆试讲里程碑。

阶段产物：project.md中的goals、criteria、level、mode及背景/范围/路径；guidance从identify推进至confirm，确认后清除待问问题。没有把拟议的试讲写成已发生。

## 字母阶段的接续样例

用户：先做方案小样，再实现，最后验收。
Agent：建议A准备：确认本阶段目标；B小样：取得可评审样例；C实现：交付可运行结果；Z验收复盘。每阶段的目标和进入下一阶段判断保存在milestone.md，具体任务用A1/B1/C1/Z1。小样已明确时直接复用，不增加空A任务。
用户：实现中发现小样漏了一项。
Agent：在B组追加下一可用号，保留已有编号；说明对C中哪些任务有真实依赖，独立工作继续。
用户：验收没通过。
Agent：保留本次证据和未通过判断，将必要返工交回对应阶段，之后继续原Z任务；最终结论仍在里程碑复盘原件。
