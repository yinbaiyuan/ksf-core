# 项目定方案：阶段引导

本方法按当前缺口选择步骤。信息充分可衔接执行，已确认步骤不重问；每阶段给简短结论和必要的校准问题。

## identify：识别真实问题

目的：识别真实问题，形成能继续推进的专业判断。

先读：先读原始请求和根卡，区分提出的做法与希望改变的结果。

引导问题示例：“这件事最终要帮谁解决什么问题？”

Agent动作：给出两三个有依据的目标解释，请用户选择或修正；保留有效的已确认目标。

阶段产物及退出：明确受益者、问题和主要目标，能够解释为何做。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=identify；满足后进入下一必要步骤。

## baseline：盘点现状

目的：盘点现状，形成能继续推进的专业判断。

先读：读取与目标直接有关的产物和材料，标明时间、事实、推断及未知。

引导问题示例：“目前已经有什么，最关键的缺口是什么？”

Agent动作：核对实际原件，指出哪些已有成果可复用；不能查到的内容留未知，不靠采访用户补本地可查事实。

阶段产物及退出：基线和目标之间的差距清楚，关键缺口有补证去向。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=baseline；满足后进入下一必要步骤。

## success：定义成功与边界

目的：定义成功与边界，形成能继续推进的专业判断。

先读：读取目标、现状、范围修正与关键约束。

引导问题示例：“出现什么可观察结果，你会认为做完了？这次明确不做什么？”

Agent动作：提出可验收条件候选，给稳定条件ID；研究任务允许排除假设，不能保证预设正面结论。

阶段产物及退出：范围、约束及完成条件可核对，用户关键取舍已明确。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=success；满足后进入下一必要步骤。

## shape：判断管理强度

目的：判断管理强度，形成能继续推进的专业判断。

先读：核对失败代价、协作和依赖、投入与战略影响。

引导问题示例：“是否有一旦选错就会造成明显损失的环节？”

Agent动作：推荐A轻量/B协作/C复杂/D战略档位并说明理由；人数与周期不是唯一依据。检查有限项目或持续迭代项目。

阶段产物及退出：管理强度、理由和重评触发明确；未知风险有相称控制。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=shape；满足后进入下一必要步骤。

## path：选择总体路径

目的：选择总体路径，形成能继续推进的专业判断。

先读：使用已确认目标和条件比较可行路径。

引导问题示例：“你倾向更快得到初步结果，还是先降低哪项关键风险？”

Agent动作：给出主方案与必要替代，解释投入、风险和先验证什么；保持总体层级，不提前铺满远期任务。

阶段产物及退出：总体做法有依据，高风险假设有验证安排。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=path；满足后进入下一必要步骤。

## confirm：校准并建档

目的：校准并建档，形成能继续推进的专业判断。

先读：汇总当前方案和仍有效的用户决定。

引导问题示例：“我把目标、完成条件和路径概括为这些，哪一点需要修正？”

Agent动作：简短回读；关键取舍已有确认则复用。通过治理接口预览、保存、读回project.md；新建先核对重名与归属。

阶段产物及退出：方案已有可信入口；缺口与下一步清楚，交拆计划继续。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=confirm；满足后进入下一必要步骤。

## 统一状态与接续

项目、里程碑、任务均使用planned/active/paused/review/completed/cancelled。未开始任务是否可做按输入、负责人、条件、承诺、依赖与容量计算；blocker只记录障碍，不替换推进状态。暂停保存原因、原环节及恢复条件，恢复前重核事实。待验收下只启动work_type=acceptance的试用、核对及补证任务；实质交付返工先将父层回到active。进行中及待验收任务计入在制，受阻不自动释放名额。已完成对象的证据变化先显示需复核，不重写历史；重开保留原验收并记录原因。

文件、字段与公共操作以[能力内治理定义](../../../partners/project-manager/references/governance.md)及其所指程序为准，不能从core/docs取得业务定义。

## 字母阶段任务的过程责任

项目总体方案仍唯一保存在project.md。里程碑内A准备任务只细化本阶段的目标、输入和路径，已有明确结果直接复用，不重新立项。
