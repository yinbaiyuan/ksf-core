# 能力路由

## 职责

为当前目标选择合适的能力，读正文确认能否承接，把可执行安排交回 Runtime。

任务切换、工作绑定和后续推进由 Runtime 负责，专业工作由所选能力执行。原安排仍然适用时直接复用，不重新发现全部对象。

## 按顺序选择

找到足以完整承接的能力，就停止扩大查找。

1. **用户明确指定。** 先分清用户要求“使用这个能力”，还是“审查、修改这个能力”。要求使用且核实适用时，直接采用，不先做全局发现。“只用这个能力”等明确限制不能自行绕过。

2. **已有安排。** Runtime 要求沿用时，只核对受影响的定义、来源和依赖；仍然适用就继续，不重启整套选择。

3. **项目预设。** 复用项目路由已提供且仍有效的根卡和检查结果。缺少或已知变化时，补读该项目根卡并执行 `project check <目录名> --json`。按配置顺序先看协作、再看搭档；适用的预设搭档可以先于全局协作。预设基本功和数据包按需支持，不作为本步的初始承接者，也不替换所选能力原有的依赖。预设不能承接时，再扩大查找。

4. **全局协作。** 通过本实例启动器执行 `context capabilities --json`，完整取得所需范围内协作与搭档的原始描述和来源。先核对有望承接的协作正文；适用时，按其分工形成安排。

5. **全局普通搭档。** 没有适用协作时，核对职责最直接、能完整承接且额外假设少的搭档。排除 `partner.ksf.competency-router`，它只在下一步兜底时使用。取舍会实质影响结果且无法确定时，带着推荐和理由交回 Runtime 澄清。

6. **一次基本功兜底。** 完整核对后，协作和普通搭档都不能承接，交回 Runtime 使用有效的 `partner.ksf.competency-router`。游离基本功的具体匹配和执行按该搭档的方法处理，本次兜底不再返回本路由重复匹配。用户明确指定的基本功或有效原安排，仍按前两步处理，不受游离条件限制。

7. **通用处理或具体缺口。** 兜底仍无匹配时，方法、事实和工具足够就交回通用 Agent 处理；不足则说明缺什么、影响哪一步，不缩减原目标。

## 核实能否承接

摘要用于找候选，正文用于确认职责、交付、适用条件和本步必要支持，不能只凭名称或关键词选择。

采用前完整取得候选主文及其标记展开的内容，核对本步必需的支持。已经完整取得且仍有效的内容直接复用；后续专业资料由所选能力按需读取，不在路由阶段一次读齐。

固定入口不作为下游候选。以实际读取结果中的 `source`、精确 `ID@版本` 和定义摘要为准。来源有歧义、版本不符或对象不可用时，保留具体问题，不按同名、排列或“最新版本”猜配。

## 有问题时怎么返回

- **发现不完整：** 核对退出码、整体及两组完整性和错误；截断先补齐。可以继续核实不依赖缺失范围的候选，但不能宣称全部不匹配或据此进入兜底。限定来源的查询不能冒充全局结果。
- **项目预设失效：** 保留原配置，返回原引用、实际问题、替代建议及适用范围，交 Runtime 在采用替代安排前说明；不能用其他版本冒充原预设。
- **执行条件不足：** 分清能力不适用与必要依赖、工具、登录或权限受阻。后者返回执行缺口，不反复重选，也不把部分可推进说成完整可执行。
- **项目事实不足：** 把具体缺口交回 Runtime 补足，不在这里另做项目归属判断。

接口参数或返回结构不清时，按需查阅 [context CLI](../../../docs/cli/context.md) 和[对象 CLI](../../../docs/cli/objects.md)。

## 交回 Runtime

返回所选能力的精确引用、实际来源和选择依据，以及需要持续使用的方法、已取得的正文、本步缺口和下一动作，连同本次目标、已有成果和有效授权一并交回。

可执行安排已经交接，或具体缺口及能继续的部分已经明确，本步骤即完成。选择完成不代表原任务已经完成。

例如：

- “审查基本功 A”：A 是审查对象，不自动把 A 当作执行方法。
- 项目预设搭档已经足够：核对后交回，不再扩大到全局。
- 全局发现失败：返回发现缺口，不跳到游离基本功兜底。
