# 搭档产出模板

归属：搭档设计。根据实际责任裁剪，不强制每项独立成章。

## 责任方案

服务对象与典型请求 → 责任及成功结果 → 必需责任/方法/支持表 → 主工作结构与关键取舍 → 原件和必要设置 → 完成与交接 → 验证题和支持缺口。

## 正式定义示意

~~~markdown
---
id: "partner.example.delivery-owner"
name: "明确服务名称"
description: "承担什么责任，何时使用，交付什么。"
version: 0.1.0
status: active
references: []
---

# 明确服务名称

## 职责与承接范围
说明服务对象、持续责任、整体结果和交接边界。

## 工作过程
确认目标及已有原件；按责任使用实际方法，取得阶段成果。
说明必须的用户参与、缺口、纠错及结果收口。

## 支持、交付与结束
方法的使用条件、输入和返回；原件归属、完成标准和下一承接。
~~~

reference 中的对象必须有实际定位；未齐支持在方案中作为缺口，不能将不存在 ID 写入正式配置后声称可用。

## 可选设置

仅为本搭档真正消费的长期偏好定义：字段、类型/范围、默认及无效处理、改变的交互或交付行为、授权更新/清除。方法参数不在此复制，工作成果不存入设置。

## 重构记录

失败任务和现行原文 → 失败层 → 修改的责任/支持/过程 → 保留内容 → 同题复查结果。整体责任改变时重新比较复用与新建，不机械增加一句禁令。
