# 搭档专业检查表

归属：搭档设计。每项记录结论、原文/任务产物位置及影响。P0 为无法可靠承接；P1 为影响持续使用；P2 为成本与表达改进。

| 编号 | 检查 | 失败信号 | 处理 |
| --- | --- | --- | --- |
| R1 P0 | 服务对象、责任和结果是否明确 | 只有角色名或“全能专家” | 重写服务题 |
| R2 P1 | 独立责任是否真实存在 | 换工具或新步骤就建角色 | 复用已有搭档或完善方法 |
| R3 P0 | 必需责任是否有真实支持 | 空引用、虚构自动化、假设专业方法存在 | 读支持正文，补具体缺口 |
| R4 P1 | 职责与专业规则归属是否清楚 | 全篇复制基本功或另定冲突算法 | 保留调用与收口，方法回原处 |
| R5 P0 | 能否从输入走到用户结果 | 只有待办或建议，没有成品和标准 | 设计产物及推进过程 |
| R6 P1 | 用户参与是否解决真实未知 | 固定问题数、重复确认、全靠用户设计 | 提供候选，仅澄清关键取舍 |
| R7 P1 | 模式和阶段能否结束或返回 | 临时支线覆盖主工作，无限共创 | 明确进入、产物和返回条件 |
| R8 P1 | 交付是否检查整体目标 | 单方法完成就宣称全部完成 | 聚合产物、处理冲突和遗漏 |
| R9 P0 | 事实、资料和能力是否可定位 | 示例被当用户事实，材料未读就下结论 | 回到原件和真实支持 |
| R10 P1 | 恢复是否复用既有原件和机制 | 自造记忆、把进度塞进个人设置 | 明确原件及必要入口 |
| R11 P1 | 设置是否有实际消费方 | 专业选项复制到角色，临时偏好自动保存 | 修正归属，无需求就删除 |
| R12 P1 | 失败能否局部处理 | 一处缺口全任务重启，隐藏降标 | 给依赖部分缺口及可行推进 |
| R13 P1 | 证据是否覆盖实际承接 | 只审文本或主路径，从未产生结果 | 执行案例并限定覆盖 |
| R14 P2 | 每段是否对承接有作用 | 角色修辞、重复系统规则、无用分类 | 删除或改成短例 |

专业方法的正确性交对应基本功检查；本表核对支持是否覆盖责任及结果是否收口。通用工艺检查按需使用能力诊断。
