# 人设路由

## 职责

让当前任务用上本实例的 USER/BOT 基础设定，并判断是否需要交给人设管理处理。

本基本功负责基础读取和需求分流；详细人设的读取、整理和长期修改由人设管理负责。

## 采用基础设定

优先使用当前上下文已经提供的 USER/BOT 原文。确认两项来自当前实例，正文完整且仍然有效后，直接采用，不重复读取。

正文没有提供、实际已经丢失或已知文件发生变化时，通过本实例启动器分别补读：

```sh
.agents/ksf config read collaboration.user --json
.agents/ksf config read collaboration.bot --json
```

已提供的文件正文在 `file.content`；通过配置接口补读时，正文在 `data.values.text`。使用返回的路径、状态和 `sha256/etag` 核对原件，不另造文件版本号。

两份文件分别处理，一项失败不跳过另一项：

- **原文存在且已完整读取：** 采用其中适用于本次任务的设定。
- **文件确认不存在：** 缺失那项按默认方式处理，不创建或补写。只有确认 USER 缺失时，可只读当前根旧 `知识/用户画像.md`，不自动合并。
- **读取失败或内容不完整：** 保留实际错误和已经取得的另一项，向 Runtime 返回缺口，不能当作文件不存在或已经读完。

切换实例后，使用新实例的原件，不沿用前一实例的人设。

## 交给人设管理的情况

基础信息足够时，结束本步骤，返回 Runtime 继续原任务。

以下情况交给有效的 `partner.ksf.persona-manager`：

- 当前问题需要基础卡之外的背景、价值观、长期目标或其他详细人设。
- 用户明确要求长期保留、修正 USER/BOT 或调整相关资料入口。

交接带上本次问题、已读原件及来源、具体缺口或修改请求、相关资料入口和已有授权。具体读取与维护按人设管理自己的方法执行。

临时表达只用于当前任务，不自动转为长期修改。例如：

- “这次简短一点”：本次采用，不保存为长期偏好。
- “以后默认简短”：交给人设管理处理。
- “结合我的价值观判断”：基础信息不足时，交给人设管理补足相关背景。

## 完成条件

USER/BOT 两项分别已有完整原文，或有明确的缺失、失败结论；当前能够采用什么、还缺什么已经清楚。需要进一步处理的需求已经交接，再返回原任务。

本基本功不修改 USER/BOT，不保存独立画像，也不把个人原文复制进 Core、项目证据或能力定义。
