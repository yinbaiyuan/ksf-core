# 游离基本功匹配

## 前提、输入与结果

仅由已进入兜底职责的基本功路由搭档使用。输入是目标、完整交付、约束、排除依据、来源范围与授权；明确指定/有效原安排不受游离筛选限制。输出一个足以完整承接的基本功及精确来源、实际结果，或无匹配/发现缺口/方法不足；不能用局部命中缩减原目标。

## 一次匹配过程

1. 调用当前根 `.agents/ksf context orphan-competencies --json`，必要时使用已明确的 `--source <源ID>`。核对退出码、complete、errors 与全体候选描述。集合来自当前有效搭档沿正式 references 的传递可达图；固定入口基本功和本匹配支持不参与。普通文字提及、历史采用和归档搭档不占用关联。
2. 有效完整空集合表示无候选；损坏、来源歧义和引用缺口表示不完整，不宣称全库无匹配。仅有不完整范围时可核实独立候选，但返回范围限制，不把缺口隐藏为否定结果。
3. 按结果、方法、输入、排除条件与工具要求比较描述，按需读取有望完整承接的候选正文和精确依赖。绑定 source、version、path、definition_digest；不能仅凭关键词、名称或摘要采用。默认选择一个完整适用者，确需组合时明确覆盖和依赖；实质取舍不明给具体推荐。
4. 真正采用前重查候选资格及定义，按原生机制读取自身配置、登记参与，然后执行业务动作直到核验交付。引用提供不等于采用。选择结果只留在本次任务安排，不写入路由搭档的静态 references，不维护反向搭档表或永久候选索引。
5. 一次兜底允许必要候选读取和比较，不重新进入能力路由或本搭档。没有适用者返回通用 Agent/具体方法缺口；输入、工具、登录或权限不足返回执行条件，不伪装无命中。定义或有效图实质变化时返回 runtime 重审受影响安排。

## 检查与示例

检查全体候选已取得、选择有正文依据、当前输入和依赖足够、动态采用后仍可再次发现该游离对象、无自递归。交回真实成果、所用方法与来源、验证及未决。本项无持久配置。

示例：无搭档关联的报告方法与请求完整匹配，读取后执行并验证报告。反例：匹配一次就把它写入静态引用，导致以后候选消失。边界：同 ID 两个源无法唯一解析时报告歧义，不能按较新版本选取。
