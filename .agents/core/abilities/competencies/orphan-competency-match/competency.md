# 游离基本功匹配

## 职责

在基本功路由搭档交来的兜底任务中，从程序给出的游离候选里找出能完整承接任务的基本功，核对适用性和使用条件，再交回搭档。

是否游离由程序按有效搭档的正式引用判断，本基本功负责判断是否适合当前任务。

## 匹配步骤

1. **取得候选。** 通过本实例启动器执行 `context orphan-competencies --json`，核对退出码、`complete`、`errors` 和全部候选描述。只有来源范围已经明确时，才使用 `--source <源ID>`。

2. **核对是否适用。** 先按描述筛选，再完整读取有望承接者的主文、标记展开内容及本步必要支持。比较交付是否完整覆盖、方法是否适用、必要输入和工具条件是否具备，不能只凭名称或关键词选择。

3. **形成选择。** 默认选择一个能完整承接的基本功；确需组合时，说清各自覆盖范围和依赖，不能用局部命中缩减原目标。实质取舍不明时，交回推荐、理由和待澄清点。

4. **确认仍可采用。** 确定选择前，再核对最新候选资格和定义，确认仍在候选集合中，实际来源、版本、路径和定义摘要与已读内容一致。发生变化时，把变化交回搭档重审，不按旧列表继续。

## 交回匹配结果

交回基本功的精确 `ID@版本`、实际 `source`、路径和定义摘要，说明选择依据、必要支持、缺口及下一动作。实际采用、当前工作安排和业务执行由搭档与 Runtime 接续。

| 当前情况 | 返回什么 |
| --- | --- |
| 候选完整且没有适用者，包括完整空集合 | 本次范围内无匹配及依据 |
| 发现不完整、来源有歧义或引用有错误 | 具体发现缺口，不能宣称全部无匹配 |
| 有适用方法，但缺输入、工具、登录或权限 | 方法选择及执行条件缺口，不当作无匹配 |

发现不完整时可以核实独立候选，但须保留范围限制；资格未能确认的候选，不能报为已可采用。

匹配选择或具体缺口已经核实并交回搭档，本步骤即完成，不在这里执行业务或保存工作绑定。

## 边界与示例

一次匹配允许必要的候选比较和补读，不返回能力路由或再次调用自身兜底。

选择只用于本次工作，不修改能力定义的 `references`，也不维护反向关联表或永久候选索引。

例如：报告基本功能完整满足要求，交回该方法及依据；方法适用但缺原始数据，交回数据缺口，不以“无匹配”再跑一轮路由。
