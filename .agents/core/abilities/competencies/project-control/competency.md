# 项目管执行

## 结果与使用

恢复真实进展并分阶段引导下一行动、执行交接、结果检查和变化处理；维护任务状态、编号上下文与必要上层协调，支持新旧项目接续。

输入：项目入口、当前任务关系、实际成果、变化和有效授权；必要外部操作身份。

## 执行方法

“继续项目／推进里程碑”先恢复其中明确当前任务，没有明确任务或有多个候选时给主建议并等待选择。任务内连续执行不扩大为整阶段顺序执行；阶段进展可据实维护，里程碑完成必须交验收基本功取得用户对该阶段的明确确认。

先读[阶段引导](references/process.md)当前步骤及必要前后衔接。每步明确目的、输入、引导、动作、阶段产物和退出条件，按实际信息判断推进；已有决定复用，关键缺口再问一两个问题。按缺口给分析与候选，允许用户修正；目标和授权已明确时连续执行当前任务，不逐阶段停等确认。

[模板入口](templates/README.md)提供当前正式文件模板；[完整交互样例](examples/guided-project.md)和[评估案例](evals/cases.json)用于检查实际过程。只读当前所需资源，不逐轮全包加载。

## 项目恢复、暂停与检查点

对尚未迁移的项目继续读取原管理主件及checkpoint_schema:1检查点，维护原任务/<任务名>.md；不因恢复自动迁移。legacy和documents不得混写，格式未知或损坏保留原件。专业结果仍交相应承接方，管理状态不启动定时器、发送或部署。

当前进度和业务事实保存在项目原件；未结束的引导使用guidance:{method,step,pending_questions}保存当前步骤、已确认结论入口和待问问题，不记录隐藏推理或另一份对话史。next_action只在所属对象维护。原件/状态、读写与冲突规则见[公共治理接口](../../partners/project-manager/references/governance.md)。

采用前读取本对象user-data；本版没有必须初始化的独立偏好或跨项目状态。写入使用读取基线和operationId，先预览再实际保存，最后读回；并发冲突保留草稿再合并。阶段结果和必要接续信息已检查时结束；模拟走查、程序回归和真实用户效果分别记录。

## 封存后的接续

恢复工作时先核对公共上下文的PROJECT_WORK_ARCHIVED提示及项目、祖先的范围。已归档时只读定位原件，停止执行；按最新etag退出受影响绑定，不能凭旧缓存继续。用户要求恢复时交验收基本功处理位置恢复，再核对目标、依赖、证据及下一步。已结束对象不自动重开，暂停对象先核对原环节。

新增任务按[治理定义](../../partners/project-manager/references/governance.md)调用公共create-task，阶段由本方法引导确定，最终任务号、文档和索引由程序生成。只支持新版字母阶段，旧项目迁移另行处理。

## 项目成果

先判断新结果是否仍在当前任务条件内；独立能力或范围扩展交拆计划，连续修改和明确返工沿原任务接续。任务主文维护当前摘要，过程材料与必要历史保留原处，避免逐轮追加流水。需要本地交付时才保存或导出到成果目录；编辑前核对草稿或固定版本，具体成果、证据和版本保护沿[治理定义](../../partners/project-manager/references/governance.md)，不为每次修改另造报告、安装包副本或编号上下文。

## 阶段确认、标准质量与执行占用

完成标准沿现有criteria表达可观察结果、核对办法及判断责任，尽量一句话说清适用场景和结果。已有标准清楚时直接执行，不另设例行确认；文件存在、摘要一致、程序成功分别支持对应结论。需要用户体验、业务判断或外部结果的条件，缺少真实依据时保持review并注明谁核对、还差什么，不由Agent自评代替。实质变更标准沿现有摘要失效与重新核验，不事后降标。

具体任务取得执行授权且准备实际操作时，先核对taskRef及稳定ID，再调用context execute获取当前聊天占用。读取、讨论、绑定和准备草稿不取得占用。其他聊天占用时只读，说明执行聊天并等待选择；明确接手前核对旧运行与未决操作已结束，不能因超时自动抢占。外部动作与执行保存前检查令牌；执行保存携带execution:{task_id,token}。完成、取消或暂停提交后释放，交还用户等待输入时主动release，后续继续重新acquire。占用不改变业务状态、承诺、在制量或授权，也不能撤回已经发出的外部操作；未知结果仍沿原operationId对账。
