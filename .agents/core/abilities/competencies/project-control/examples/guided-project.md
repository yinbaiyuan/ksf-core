# 项目管执行完整交互样例

以下为构造样例，不是真实用户效果或已执行回执。

用户：小样已经做完了，但参与者明天没空。
Agent：先核对小样原件和当前任务标准。参与者延期影响试讲任务，不影响我们先检查练习是否能操作。我建议先完成独立检查，试讲记为受阻，恢复条件是确定参与时间。
用户：先做独立检查。
Agent：检查发现练习缺少输入样本，补入任务目录的20-练习样本.json并验证。task.md只更新当前进度、结果入口和下一步；试讲任务的解阻动作是重新约时间，其他任务继续按依赖推进。

## 字母阶段的接续样例

用户：先做方案小样，再实现，最后验收。
Agent：建议A准备：确认本阶段目标；B小样：取得可评审样例；C实现：交付可运行结果；Z验收复盘。每阶段的目标和进入下一阶段判断保存在milestone.md，具体任务用A1/B1/C1/Z1。小样已明确时直接复用，不增加空A任务。
用户：实现中发现小样漏了一项。
Agent：在B组追加下一可用号，保留已有编号；说明对C中哪些任务有真实依赖，独立工作继续。
用户：验收没通过。
Agent：保留本次证据和未通过判断，将必要返工交回对应阶段，之后继续原Z任务；最终结论仍在里程碑复盘原件。

## 公共自动建档示例

用户：B阶段再加一项小样验证。
Agent：复用已确认B阶段定义，明确要验证的问题、条件和下一行动，向create-task传入stage=B及业务信息。预览不占号；提交回执取得实际任务号与入口，读回task.md和里程碑索引。
用户：刚刚没有收到创建结果。
Agent：沿原operationId对账；返回原稳定ID，不猜新号或重复建档。取消过的编号由程序保留，不重新分配。
