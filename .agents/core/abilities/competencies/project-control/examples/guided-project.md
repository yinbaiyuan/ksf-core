# 项目管执行完整交互样例

以下为构造样例，不是真实用户效果或已执行回执。

用户：小样已经做完了，但参与者明天没空。
Agent：先核对小样原件和当前任务标准。参与者延期影响试讲任务，不影响我们先检查练习是否能操作。我建议先完成独立检查，试讲记为受阻，恢复条件是确定参与时间。
用户：先做独立检查。
Agent：检查发现练习缺少输入样本，在练习实际原件中补齐并验证，任务引用其入口；只有用户明确要求留作编号上下文时才另建编号条目。task.md更新当前结果和缺口，next_action沿元数据维护；试讲解阻动作是重新约时间，其他工作按真实依赖推进。

## 字母阶段的接续样例

用户：先做方案小样，再实现，最后验收。
Agent：建议A准备：确认本阶段目标；B小样：取得可评审样例；C实现：交付可运行结果；Z验收复盘。每阶段的目标和进入下一阶段判断保存在milestone.md，具体任务用A1/B1/C1/Z1。小样已明确时直接复用，不增加空A任务。
用户：实现中发现小样漏了一项。
Agent：先比较原小样任务的目标与条件。同一小样缺项接续原任务补齐；新增独立验证且确需单独安排时，才在已确认B阶段调用公共create-task追加，并说明真实依赖。已结束任务的明确返工保留原验收和重开原因。
用户：验收没通过。
Agent：保留本次证据和未通过判断，将必要返工交回对应阶段，之后继续原Z任务；最终结论仍在里程碑复盘原件。

## 公共自动建档示例

用户：B阶段再加一项小样验证。
Agent：复用已确认B阶段定义，明确要验证的问题、条件和下一行动，向create-task传入stage=B及业务信息。预览不占号；提交回执取得实际任务号与入口，读回task.md和里程碑索引。
用户：刚刚没有收到创建结果。
Agent：沿原operationId对账；返回原稳定ID，不猜新号或重复建档。取消过的编号由程序保留，不重新分配。

## 以任务为执行单位与阶段确认

以下为构造样例，不代表真实用户验收。

用户：在已确认的“首版Demo可评审”阶段，先编译安装现有代码。
Agent：在该阶段复用或建立编译安装任务，连续完成必要检查与安装；完成后只建议下一任务，不新增编译安装里程碑。
用户：接着部署主题循环预览。
Agent：在原阶段判断它与已有成果的关系，独立成果建任务，相同成果接续；维护具体taskRef。
用户：继续这个里程碑。
Agent：恢复明确当前任务；若尚未选定，说明主建议及理由，等待选择。
用户：不要再试了，可以了。
Agent：停止对应尝试，保留证据和未决；这条局部反馈不作为阶段确认。
Agent：本阶段任务和证据预检已通过，复盘保留草稿，阶段待验收。向用户列出阶段、交付版本、逐项证据与遗留。
用户：我确认这个里程碑按刚才列出的范围通过，可以完成。
Agent：核对依据未变，记录实际表述、时间、原生轮次和确认范围，同一事务完成复盘和里程碑；不启动下一阶段。

## 成果归位与修订示例

用户：继续完善还未固定的汇报PPT和PDF草稿，之后交付，同时需要设备固件。

Agent：先核对原件用途和现有引用。未固定工作草稿可持续维护，已采用基线、交付、回退或验收依据不覆盖；当前结果与证据分别引用，不另造逐次成果报告。

实际安排：草稿中的改字、排版持续维护当前文件，源文件和导出文件保持对应。形成交付时固定汇报方案-v1.pptx、汇报方案-v1.pdf和对应固件；之后修订已交付v1才生成可识别的新版本并保留原版。不同固件或安装包的构建身份不混用；有可靠制品历史时不为每次构建重复导出，必要交付和回退版本仍保留。旧报告、验收及项目资料不自动迁移或清理。

## 阶段确认、标准质量与执行占用

用户要求交付汇报PDF：将“文件生成”具体化为内容覆盖约定主题、实际打开版式完整，汇报可用性由用户实际核对。程序项通过而体验反馈未取得时保持待验收。新聊天接续先读原件，遇到旧聊天占用只读说明，不重复导出或安装；用户明确接手并核对旧操作结束后再取新令牌。里程碑所有任务完成时整理预检，取得针对本阶段的真实确认后沿同一治理事务收口。
