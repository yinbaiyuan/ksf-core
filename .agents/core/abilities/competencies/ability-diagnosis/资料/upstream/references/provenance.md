# 出处与证据链（凭什么信这套标准）

> 什么时候读：有人问"这套标准哪来的、凭什么信"时；或需要说明某条规则的来源时。
> 一句话：说清楚这套标准从哪里提炼、经过哪些检验、检验能证明到什么程度。
> 阅读提示：文中评分都是评审组的定性判断，不是实验室测量；每处都标明了局限，欢迎按相同评价维度复核。

## 一、从哪里来（三个来源）

### 1. 官方技能库审计
逐一盘点 Anthropic 官方 332 个技能（即常说的"300+"）的调用方式，按真实用法排出各条规则的优先级，不凭个人口味。

### 2. 旗舰案例拆解
重点拆解了下面这些官方技能，七大范式（见 `paradigms.md`）就是从中归纳出来的：

| 案例 | 学到的做法 |
|---|---|
| skill-creator | 元工程化：用技能造技能，自带校验 |
| doc-coauthoring | 协同共创：分阶段推进，关键节点等人确认 |
| frontend-design | 去掉"AI 塑料感" |
| slack-gif-creator / pptx / xlsx | 黑盒工具链：容易出错的逻辑写进脚本 |
| canvas-design / algorithmic-art | 双步创构：先写设计宣言，再做作品 |
| internal-comms / brand-guidelines | 分拣路由：按需求找到对应规范 |
| webapp-testing | 侦察行动：先看清环境再动手 |
| mcp-builder | 评测驱动开发（EDD）：先定测试，再写实现 |
| web-artifacts-builder | （原文只列了名字，未注明对应做法） |

### 3. 三类资料合流
- **官方教程**：打地基——技能结构、YAML、MCP、分发；
- **一家中文头部技能工厂的组织方法论**：讲推行——拆建推练、知识固化、分级治理；
- **本标准**：讲工程——把前两者落成可执行的规则、检查表和评测方法。

## 二、经过哪些检验

### 检验 1：三份指南横向对比

| 维度 | 官方教程 | 工厂方法论 | 本标准 |
|---|---|---|---|
| 实战落地性 | ★★★★☆ | ★★★☆☆ | ★★★★★ |
| 知识宽度 | ★★★★★ | ★★★★☆ | ★★★★☆ |
| 工程深度 | ★★★☆☆ | ★★★★☆ | ★★★★★ |
| 方法论独创性 | ★★★☆☆ | ★★★★★ | ★★★★☆ |
| **综合** | **B+（权威必读）** | **A（思维启蒙）** | **S（工业级标杆）** |


### 检验 2：与官方 skill-creator 对比

| 维度 | 官方 skill-creator | 本标准 |
|---|---|---|
| 物理原子性 | ★★★★★ | ★★★★☆ |
| 逻辑架构力 | ★★★☆☆ | ★★★★★ |
| 工程生命周期 | ★★★★★ | ★★★☆☆ |
| 量化可测量性 | ★★☆☆☆ | ★★★★★ |
| 审美与意图锚点 | ★★★☆☆ | ★★★★★ |
| **综合** | **85（准入证书）** | **96（大师手册）** |

结论：两者互补，不是替代。官方擅长"能跑通"，包括文件结构、打包和完整的生命周期管理；本标准擅长"做得好"，包括架构选型、量化评估和审美要求。在"工程生命周期"一项上，本标准仍弱于官方。

### 评分方法与局限

- 检验 2 的星级是结构化定性评分（每项 1–5 星），由同一个评审组按同一组题目对照打分。检验 1 的评审方式，原始记录没有单独说明。
- 综合分 85 / 96 是评审组在星级基础上折算出的整体判断，**不是星级的直接换算**：两者的星级合计分别为 18/25 和 22/25，和综合分之间没有固定公式。星级表完整保留，方便任何人复核。
- 局限：只有一个评审组；以 2026-10 定版时的口径为准；只适合同口径下的相对比较，不能当作跨体系的绝对分数。
- 想质疑时：可以核对星级表，并按相同评价维度重新评审；重新评审的结果可以推翻本文结论。


## 三、怎么一步步改出来的（版本演进）

本标准不是一次写成的，而是每一轮都对照外部标准找短板、补短板。

| 轮次 | 做了什么 | 结果 |
|---|---|---|
| 1 破题 | 用三份指南做基准对比（检验 1） | 暴露短板：具体操作层面写得太空 |
| 2 原子化 | 审计官方 docx / xlsx 案例 | 产出第一版"必做 / 禁止"清单，按不重不漏（MECE）分类 |
| 3 极致化 | 定下 10×10 结构和 P0–P3 排序 | 全量审计 332 个官方技能的调用方式，据此排出优先级 |
| 4 升维 | 加入量化指标（ZSAR、触发率、Token）和第七范式（SDK 联动） | 量化体系和第七范式进入标准 |
| 5 合龙 | 与官方 skill-creator 对比（检验 2） | 吸收官方的物理边界指标，定版 |
| 6 评测化（2026-08） | 官方 skill-creator 发布"测试、衡量、改进"（Test, measure, and refine）大更新，从"创建 + 打包"升级为"创建 + 评测 + 优化"；本标准跟进吸收 | 评测方法落进 `eval-loop.md`，补上"造完要测"这一环 |

第 6 轮参考的官方文章：《Improving skill-creator: Test, measure, and refine Agent Skills》

## 四、实战验证：一次真实体检

2026-05，用本标准给"CEO 助理"的 4 个技能做了体检，发现 6 项问题：

1. [P0] 缺初始对话协议 → 做深度研究、执行任务时可能跑偏方向
2. [P1] 缺 examples/ 满分样本 → AI 知道格式，但不知道"好"长什么样
3. [P1] 分析方法写在正文里 → 浪费 Token，应挪到 references/
4. [P2] 任务路由缺决策树
5. [P2] YAML 简介（description）的触发效果可以优化
6. 语言风格判定为"不改"：描述性中文是对话型技能的设计意图，不是缺陷（示范：不机械套表，按场景判断）

这次验证说明了什么：
- **能说明**：这套检查表能在真实技能里找出具体问题，并且会区分"缺陷"和"有意的设计"。
- **不能说明**：只有一次体检、4 个技能，还不能证明对所有类型的技能都同样有效；本文也没有记录修改后的效果是否提升。

报告样式见 `examples/perfect-audit-report.md`（节选）。
