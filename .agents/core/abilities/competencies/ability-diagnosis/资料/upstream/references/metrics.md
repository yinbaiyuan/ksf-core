# 五维量化标尺（会诊评级）

> D 模式必读；B 模式定级时加载。
> 一句话：用同一套 5 个指标，衡量一个技能好不好用，或者比较两个技能谁更好。

## 五个维度

### 1. 任务完成效率（Tool Call Efficiency）
- 定义：完成同一复杂任务的平均工具调用/消息往返次数。
- 参考及格线：高阶 Skill 通过工作流编排 + 侦察并行，往返次数减少 30%+；无多余澄清询问。（只比较结果都合格的那几次；按要求开工前的确认不算“多余询问”。）
- 本地测法：同任务分别“不用技能”和“用技能”各跑 3 次，数往返次数。默认数你能看到的对话轮次（你发一条 + AI 回一条 = 1 轮）；平台能显示工具调用记录时，再另外记录调用次数。

### 2. Token 占用量（Token Usage）
- 定义：单位产出消耗的背景 Token 数。（做出同样的结果，要占用多少文字量（Token），占得越少越好。）
- 参考及格线：远低于对话中重复粘贴 prompt；严禁全量重写长文档，只传 diff。（当前环境看不到 Token 统计时，写“未实测”，不要估算填数。）
- 本地测法：平台能显示 Token 统计时，对比用技能前后做出同样结果的消耗。看不到统计时写“未实测”；可另外记录“技能每次必须读的文件总字数”作为参考，但要标明这是文件体积，不是实际消耗。

### 3. 触发准确率（90% 原则）
- 定义：20 条应该触发技能的查询（含改述 paraphrase）中，AI 自动调用技能的成功率。（用户换着说法提需求时，AI 能不能自己想起来用这个技能。）本项不衡量不应调用时的误触发情况。
- 参考及格线：≥ 90%。需要用户显式点名或反复提特定词才能唤醒 = description SEO 失败。
- 先判断能不能测：当前平台会自动调用技能，并且界面能看出这次是否调用了，才往下测；平台只能手动选择技能或智能体时，本项写“不适用”；看不出是否调用时，写“未实测”。
- 本地测法（详见 `eval-loop.md` §2）：准备 20 条应该触发的查询，覆盖技能的使用场景及同一意图的不同说法，不加入不应触发的反例；每条 3 遍取稳定值；60/40 分训练/保留集，在 description ≤100 词的前提下，按保留集分数选优。
- 机制提醒：模型只对"自己搞不定的复杂任务"查技能——太简单的查询测不出触发，出题要够真实够复杂。

### 4. 无修改采纳率（ZSAR，Zero-Shot Acceptance Rate）
- 定义：产出物不做任何人工修正直接通过审核落地的概率。衡量针对性的终极 KPI。
- 参考及格线：高阶实战任务 ≥ 85%；支持靶向迭代（对 15% 错误做精准 Prompt Patch，而非整体重刷）。
- 本地测法：记录该 Skill 最近 N 次真实产出，人工零修改通过的比例。（报告时写明 N 是多少、由谁判断是否“零修改”；N 很少时，只作参考，不下结论。）

### 5. 自治治理等级（C/B/A/S）
| 等级 | 名称 | 含义 | 人类角色 |
|---|---|---|---|
| C | Co-Pilot | 提供参考 | 每步确认 |
| B | Reviewer | AI 全稿 | 修正性审计 |
| A | Autonomous | 标准环境自动执行 | 日志抽检 |
| S | Supervised Self-Evolve | 自回归测试 + 自动优化闭环 | 只看趋势 |
用大白话说：
- C 副驾驶（Co-Pilot）：AI 只给建议，每一步都由你确认；
- B 你当审稿人（Reviewer）：AI 写出完整稿，你负责修改把关；
- A 自动驾驶（Autonomous）：标准情况下 AI 自己做完，你偶尔翻记录抽查；
- S 受监督的自我进化（Supervised Self-Evolve）：AI 自己测试、自己改进，你只看整体趋势。

评级时标注该 Skill **当前等级**与**目标等级**；升到更高一级时，要在流程的过关标准（Exit Criteria）里写清：哪些节点必须停下来等人确认（人类中断器）。评级时注明平台限制：当前平台不支持无人值守运行时，最高只能评到 B，并写明“受平台限制”。

## 会诊输出格式（D 模式产出物）

```markdown
# 技能对比报告（会诊）：<技能 A> vs <技能 B> · <日期>

## 一句话结论
<留哪个 / 合并 / 退役 / 各管一块>，主要理由：<一句话>

## 一、五个指标逐项对比

| 比什么 | <技能 A> | <技能 B> | 依据（测试记录或原文行号） |
|---|---|---|---|
| 1 完成同一件事要来回几次（任务完成效率） | | | |
| 2 占用多少文字量（Token 占用量） | | | |
| 3 该用时能不能被想起来（触发准确率） | | | |
| 4 不改就能直接用的比例（ZSAR） | | | |
| 5 AI 能独立做到哪一步（自治等级 C/B/A/S） | | | |

（没有实测数据的指标写“未实测”，不要凭感觉填数字。）

## 二、建议（裁决）
- **结论**：<留谁 / 合并 / 退役 / 各管一块（各司其职）>
- **怎么分工**：<如果两个都留，各自负责什么>
- **谁来执行**：这里只给建议；真正合并或删除，由用户决定后再执行。

```

## 使用纪律

- 禁止把未实测的数字当结论；未实测就写"未实测"。
- 横评只比**同任务域**的 Skill；跨域比较无意义。（例：两个都是批改作业的技能可以比；拿批改技能和画图技能比，没有意义。）
- 任何“退役 / 合并”结论只做建议，由用户决定是否执行
