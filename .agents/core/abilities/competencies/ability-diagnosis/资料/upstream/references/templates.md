# 全套文档模板与生成 SOP

> 什么时候读：A 模式（创建）写蓝图和文件时；C 模式（处方）写修改补丁时。
> 一句话：照着这里的模板写，不用每次从零发明格式。
> 与官方 skill-creator 模板对齐。

## 一、YAML 标准块（P0：必须有）

YAML 块就是 SKILL.md 最顶上、两条 `---` 之间的那几行。AI 平时只看得到这里，所以它决定技能会不会被想起来。

```yaml
---
name: <kebab-case，动词词组，如 research-analyzer>
description: <身份定义> + <三个触发场景短语> + <独家资源列表> + <产出物属性>。≤100 词；这里必须写清使用时机，正文也可以补充。
---
```

- name：用小写英文加短横线（kebab-case），最好是动词词组。
- description：写清 我是谁 + 三个使用场景 + 独有资源 + 产出物特点；≤100 词。这里必须写清使用时机；正文可以补充使用时机和分支路由，但不能代替 description 中的触发说明。

例：`深度研究报告专家。在需要进行全网信息检索、学术论文摘要提取或构建行业竞争格局图谱时使用。包含独家 search_scripts。产出物具备 McKinsey 风格的顶级排版。`

**写得主动一点（pushy 原则）**：description 要明确写出应调用的场景（如"凡用户提到 X / Y / Z 都要用本技能，即使没点名"），但总长度必须 ≤100 词；超过时压缩重复措辞，详细使用时机可放正文补充。触发效果用 `eval-loop.md` §2 的方法实测，不拍脑袋。

## 二、初始对话协议模板（P0：必须有）

意思是：接到多步任务时，先说清计划、等用户点头，再开工。

> 我已识别到您的 [需求名称] 意图。我计划按照以下架构进行：1. [Phase 1]；2. [Phase 2]……产出物将遵循 [调性标准]。是否现在开始？

## 三、Anti-Slop 词库（去掉"AI 塑料感"）

"塑料感"指空泛、套路、放哪都通用的 AI 腔。

- **强制禁用词**：Smart / Seamless / Empower / Comprehensive / Innovate / Beautiful / Good。
- **替换办法**：换成具体参数（如"Latency < 200ms"、"12pt"）或具体对标（如"Like Stripe API docs"、"Like ex01"）。
- **美学宣言关键词库**（写审美要求时可选用）：视觉类 Pristine / Meticulous / Minimalist / Hierarchical；思维类 Risk-first / First-principles / Logical pre-filling。

## 四、SKILL.md 主控模板

SKILL.md 是技能被调用后 AI 第一个读的文件，按下面的骨架写：

```markdown
---
<YAML 标准块>
---

# <技能显示名>

## 核心目标与审美宣言
<强力谓词定义的专业调性；审美类项目此处为 500 字宣言，实现必须 100% 呼应>

## 触发与决策路由
<何时启动 + if-then 决策树（多分支时）>

## 核心工作流
### Phase 1: <名称>
- 执行指令：<祈使句>
- 退出条件：<可判定的硬标志>
<更多 Phase…>

## 执行约束与红线
- <红线规则>

## 资源引用
- [何时读哪个 reference](references/xxx.md)；>10k 字文件附 grep 关键词
```

各部分要写什么：
- 核心目标与审美宣言：用有力度的词定下专业调性；审美类项目这里写约 500 字的设计宣言，后面的实现必须 100% 对得上。
- 触发与决策路由：什么时候启动；有多个分支时，写成"如果……就……"的决策树。
- 核心工作流：每个阶段（Phase）写两样——用命令句写的"执行指令"，和能明确判断是否完成的"退出条件"（过关标准）。
- 执行约束与红线：绝对不能做的事。
- 资源引用：什么时候读哪份参考文档；超过 10k 字的文档附上检索关键词（grep）。

## 五、目录样板

```text
skill-name/
├── SKILL.md          # 意图路由、性格锚点（行数建议少于 500 行）
├── references/       # 静态知识、API 文档、规则集（按需加载）
├── scripts/          # 黑盒执行/验证脚本（只读用法，配 --help）
├── examples/         # 满分作业范本（搬运结构，非内容）
└── assets/           # 模板、字体、图标（不进上下文）
```

每个位置放什么：
- SKILL.md：判断用户要做什么、定下技能的性格（行数建议少于 500 行）。
- references/：参考资料、接口文档、规则集，用到才读。
- scripts/：AI 不看内部、只管运行的脚本（只看用法说明，配 `--help`）。
- examples/：满分作业样板，学它的结构，不抄它的内容。
- assets/：模板、字体、图标等素材，不进入 AI 的阅读内容。

禁止创建：README / INSTALLATION_GUIDE / QUICK_REFERENCE / CHANGELOG 等人读文档

## 六、references/ 与 examples/ 模板

references 模板：标题 → 使用说明（何时读）→ 目录（>100 行时）→ 分章内容。
examples 模板：场景描述 → 满分输出展示 → 尾注"仅供模仿结构神髓，严禁生搬硬套内容"。

## 七、六阶段生成 SOP（A 模式全流程）

注意：这里的 A–F 是"创建"内部的六个步骤，和 A/B/C/D 四种模式不是一回事。

| 阶段 | 动作 | 退出条件 |
|---|---|---|
| A 需求采集 | 问 5-8 个最小必要问题（领域/触发语义/产出形态/环境约束/脆弱点/质量门槛/复现需求/品牌 token） | 范围 + 硬门槛 + 工具清单清晰 |
| B 范式选择 | 按 paradigms.md 定 1-2 个主导范式 + 理由 + 固定/可变合约 | 主范式与质量门槛明确 |
| C 目录设计 | 最小而完整的包结构，逐文件角色 | 每个文件的存在理由成立 |
| D 生成主文件 | 按模板四产出 SKILL.md（祈使句、行数建议少于 500 行、seed 快照如涉及随机） | 一版可直接投入使用 |
| E 验证闭环 | 六项自检：触发可测 / Exit Criteria 可判定 / 固定可变清晰 / 黑盒失败路径覆盖 / 可复现 / 指标可采集 | 无阻断性缺陷 |
| F 交付 | 主文件 + 扩展建议；复杂件附 1-2 个参考链接 | 用户验收 |

每一步用大白话说：
- **A 需求采集**：先问清楚要做什么。只问 5-8 个真正必要的问题，范围包括：什么领域、用户会怎么说来触发、产出长什么样、环境有什么限制、哪里最容易出错、质量底线是什么、需不需要每次结果一致、有没有品牌规范（品牌 token）。→ 过关标准：范围、硬性底线、要用的工具都清楚了。
- **B 范式选择**：按 paradigms.md 选 1-2 个主导结构，写清理由，以及"固定/可变合约"（哪些锁死、哪些让 AI 发挥）。→ 过关标准：主结构和质量底线都明确了。
- **C 目录设计**：设计最小但够用的文件结构，每个文件写清是干什么的。→ 过关标准：每个文件都说得出为什么要存在。
- **D 生成主文件**：按第四节模板写出 SKILL.md（用命令句，行数建议少于 500 行，不单凭行数判定不合格；如果涉及随机生成，要记录随机种子 seed 和参数，方便复现）。→ 过关标准：写出来的这一版可以直接拿去用。
- **E 验证闭环**：六项自查——触发能不能测；每步的过关标准能不能明确判断；固定和可变的部分是否分清；脚本失败时有没有处理办法；结果能不能复现；效果指标能不能收集。→ 过关标准：没有会卡住使用的问题。
- **F 交付**：交付主文件和后续扩展建议；复杂的技能附 1-2 个参考链接。→ 过关标准：用户验收通过。

## 八、处方补丁规范（C 模式专用）

一句话：修技能要像做外科手术——只动有问题的地方。

- 一个问题 = 一个最小改动（diff）；修 P0（致命问题）时严禁顺手改无关内容。
- 补丁格式：`[必修 P1-2] <文件>:<行号范围> str_replace <旧> → <新>，理由一句话`。方括号内写对应条目的完整编号，必须带“必修”或“红线”前缀；示例编号对应“外科手术式编辑指令”。
- 涉及随机生成的：补丁必须保留随机种子（seed）和参数快照的约定。
- 打完补丁要复查：重新检查受影响的条目，给出修改前后对比。
