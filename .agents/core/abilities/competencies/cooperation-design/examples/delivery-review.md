评估用模拟案例。制作责任采用[搭档设计完整样例](../../partner-design/examples/delivery-planner.md)，报价方法采用[基本功设计完整样例](../../competency-design/examples/quote-check.md)。评估时提供这些完整定义，不宣称本实例安装了示例能力。

## 成立与取舍

用户需要“可审查方案”和“独立核验意见”两个成果。制作与核验分别有自己的产物和判断，存在成果依赖和返工关系，采用成果接力加复核反馈。它可由同一 Agent 分别承担责任；不假定两个后台 Agent 已经运行。

如果只是制作搭档自己读、写、检查，则留在其内部，不建立本协同。

# 交付方案与核验协同

## 整体结果

制作与独立核验共同交付同一范围、同一有效版本的方案及核验意见。开始时确认当前要求是审查稿还是可实施交付，以及允许保留哪些未决。

## 责任与推进

方案制作搭档维护方案原件，依据需求、材料及报价方法形成稿件，注明来源、采用选择、差异和未决。

核验搭档接收需求口径、方案版本、专业核对结果和未决；输入不足以核验时指出缺失及提供方，不将“文件已收到”作为接手完成。可独立核验的部分可以先做。

核验返回逐项意见、对应依据和结论，由方案制作方修订原件。核验方不覆盖方案正文；协调责任由当前执行本协同的 Agent 承担，跟踪意见是否得到处理并核对整体结果。

## 返工与变化

退回要说明哪个标准未满足、影响什么、由谁补证或修改。修改后核验受影响项和相关一致性；没有新证据而重复争议时，协调方整理选项、代价和推荐，超出授权的取舍交用户。

需求、报价或方案版本变化时识别使用了变化输入的成果，重核相关专业结果与核验意见。能证明未受影响的内容保留；旧核验不能直接作为新版已通过。

## 完成

本次必需方案和核验意见可读、版本一致、问题已处理或按阶段约定列明、后续责任清楚时结束。要求可实施交付时，阻断性未知未解决不能完成；仅要求审查稿时可交付明确未决，但不能声明可实施。

必要保存沿现有任务记录与专业维护方式执行，不建立额外状态库，不隐式发送或发布方案。

# 交付核验搭档

核对需求与方案的范围、依据、版本及必要专业检查结果。先读当前需求、方案和来源，确认本次验收阶段，不依赖制作方口头说已完成。

逐项检查需求是否有对应交付、选择是否有依据、未决是否影响当前阶段。涉及报价变更时取得引用的报价核对方法，按其规则核对并保留结果，不另写算法。

以方案版本、依据位置、问题、影响和返回责任形成意见。输入缺失时说明能核验什么和仍缺什么；不补造事实，不覆盖制作方原件。

修改后核验受影响内容及其一致性。只有本次阶段必要条件满足才给对应结论；审查稿可读不等于实施条件齐全。意见、未决和返回要求交付后结束本次核验。
~~~

## 变化演示

需求由“不含安装”变为“包含安装”，原方案和核验都使用过旧范围。制作方补范围并用报价方法重核；核验方对新版范围与报价结论复查。没有变化的设备参数及其来源保留。若安装费用未知，审查稿明确列缺口，可实施结论继续等待。
