# 协同专业检查表

归属：协同设计。逐项给结论、证据位置和影响。P0 阻止可靠合作，P1 影响持续推进，P2 影响成本与表达。

| 编号 | 检查 | 失败信号 | 修正 |
| --- | --- | --- | --- |
| C1 P0 | 合作必要性是否成立 | 单搭档步骤人为分角色 | 合回内部过程或任务安排 |
| C2 P0 | 整体结果和标准是否明确 | 各做各的，没有共同交付 | 从成品重定范围与标准 |
| C3 P0 | 成果和关键决定是否有人负责 | 无人收口或多方覆盖同一原件 | 明确生产、维护及裁决 |
| C4 P0 | 参与责任和支持是否真实可用 | 只有待创建名称 | 补支持或声明不能承诺部分 |
| C5 P0 | 初始输入能否推动流程 | 循环等待、依赖永远不满足 | 重算关系，形成解阻动作 |
| C6 P1 | 交接是否足以接手 | 只写“交给下一位”，无版本和依据 | 定义原件与接手条件 |
| C7 P1 | 不合格是否能定位返回 | 全体重做或无人处理 | 明确问题、返回方和修订归属 |
| C8 P1 | 上游变化能否影响下游判断 | 源稿已改却沿用旧验收 | 沿实际使用关系复查 |
| C9 P1 | 循环是否有进展与出口 | 无限互退或只数轮次 | 明确改动依据及协调去向 |
| C10 P1 | 并行与汇合是否安全合理 | 争写原件、版本口径不一致 | 独立输入、唯一维护和汇合检查 |
| C11 P1 | 整体完成是否有证据 | 节点全结束就宣称成功 | 核对覆盖、一致性及未决 |
| C12 P1 | 合作规则与专业方法是否分开 | 协同复制算法并覆盖专业标准 | 保留交接与整体检查 |
| C13 P1 | 参数及进度是否各有归属 | 复制各方设置、另建状态中枢 | 规则归协同，进度归原件 |
| C14 P2 | 结构是否付出必要成本 | 无用角色、关卡和读取 | 去掉不改变结果的交接 |

专业审查要看实际交接和变化案例。元数据、引用、资源和加载可由现有程序检查；它们不能判断一套合作在业务上是否成立。通用工艺审查按需使用能力诊断。
