# 系统发行

## 输入与结果

输入是用户的构建、正式发布或故障恢复要求、实际实例根、Core 版本、精确 SHA 与授权范围。本地构建另需纯系统源码根和新输出目录。结果是可检查的本地产物或已核实的 Core Release。实现、提交、PR、正式发布与实际安装分别记录。

## 方法

1. 读取[Git 规则](../../../docs/git.md)。核对唯一官方 Core 的 `core-main`、版本、精确提交、同版本标签及既有资产；个人 origin、main 和未合并的系统改动不能成为正式源码。不自动递增版本，不手填安装凭据。
2. 用户只要求讨论、实现、构建或验证时不触发正式发布。明确要求发布后，核对实际远端 Actions 与发起账户权限，从指定 Core 仓库的 core-main 发起 release.yml；不查询或写入第二个 Workspace 项目，不要求跨仓库 App 令牌。
3. 发行先检查官方 Core 默认分支和模板标记、最终提交属于稳定主线、完整 Mac/Windows 原生证明。匹配的可信证明可复用，缺失则补全；本地快速或模拟平台不替代原生全量。准备仅构建一次，冻结 artifact ID、Core SHA、版本与索引摘要，发布作业复用该产物。
4. 本地构建核对纯系统提交与随包平台，执行必要验证及 `release build`，检查唯一 Core 包、索引和本地 ksf/ 检查目录；该目录不是第二个发布产品。allow-dirty 只供明确的本地试验，不能正式发布。只要求构建时交付本地产物。
5. 发布先预览，再按实际授权执行。未知上传或触发响应先按原请求与同一资产对账；重试不能替换已公开资产或让同版本标签换源。记录请求时间和运行标识，候选不唯一时保留现场，不直接重发。
6. 核对 tag、来源、资产摘要和公开状态，交付实际链接及未决项。程序测试、真实 GitHub 设置、远程 CI、正式发布和实例验收各自留证。失败保留冻结产物与原错误，不删除远程资产换取重试成功。

## 边界与验证

凭证通过工具已有认证取得，不写日志、产物或用户配置。官方根工作流的规范源位于 Core 的 distribution/repository，贡献时显式投影，不覆盖个人实例根 CI。

正例：已合入 core-main 的版本通过双平台证据后只发布 Core。反例：打包个人实例、使用个人历史替代内核、把模拟 API 当真实发行。边界例：资产上传响应未知时核对并复用同一资产。

技术协议由[发行说明](../../../docs/distribution.md)与[release CLI](../../../docs/cli/release.md)持有，平台验收按实际证据报告。
