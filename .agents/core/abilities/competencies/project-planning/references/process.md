# 项目拆计划：阶段引导

本方法按当前缺口选择步骤。信息充分可衔接执行，已确认步骤不重问；每阶段给简短结论和必要的校准问题。

## align：核对方案

目的：核对方案，形成能继续推进的专业判断。

先读：恢复project.md及最新决定，检查目标与完成条件是否足以安排工作。

引导问题示例：“这次先安排哪个已经确定的目标？”

Agent动作：缺方向时衔接定方案并带上已有答案；目标已清楚时直接采用，不再重新立项。

阶段产物及退出：规划所承接的目标和边界明确。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=align；满足后进入下一必要步骤。

## decompose：判断子项目

目的：判断子项目，形成能继续推进的专业判断。

先读：核对独立成果、责任、验收和单独管理的必要性。

引导问题示例：“哪一部分值得独立维护目标和推进节奏？”

Agent动作：给出保持单项目或拆子项目的建议；确需拆分时为每个子项目调用定方案，使用setParent同步父子两端。

阶段产物及退出：分层能减少协调成本；每个子项目有独立目标，未因目录或聊天数量强拆。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=decompose；满足后进入下一必要步骤。

## milestones：定义阶段结果

目的：定义阶段结果，形成能继续推进的专业判断。

先读：由项目完成条件倒推可检验的中间成果。

引导问题示例：“先拿到什么阶段结果，才值得进入下一步？”

Agent动作：提出一个或多个里程碑，说明目标、达成条件与必要依赖；当前阶段细，远期阶段粗，避免按日历空切。

阶段产物及退出：当前里程碑能独立验收，阶段间关系清楚。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=milestones；满足后进入下一必要步骤。

## tasks：拆当前任务

目的：拆当前任务，形成能继续推进的专业判断。

先读：读取当前milestone.md及相关输入。

引导问题示例：“为了拿到这个阶段结果，现在最需要解决哪几个问题？”

Agent 动作。把新里程碑目录直接放在项目根目录。先明确用户采用的字母阶段，再将任务名称、criteria、负责人、输入和下一步交公共 create-task 预览、提交和读回，由程序在里程碑内取号、创建任务目录和 task.md，并维护索引。任务也可在执行中逐步产生。规划时引用已有共用材料。用户主动要求将材料留作上下文时，按其作用范围创建编号条目。

阶段产物及退出：任务覆盖阶段结果，大小足以检查进展与交接。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=tasks；满足后进入下一必要步骤。

## dependencies：连接责任与依赖

目的：连接责任与依赖，形成能继续推进的专业判断。

先读：核对实际输入、协作、容量和关键确认节点。

引导问题示例：“哪些结果必须先有，哪些可以独立推进？”

Agent动作：只为真实前置设置depends_on；父子归属不当硬依赖。未知负责人/日期不猜填，高返工成本选择前置确认。

阶段产物及退出：无依赖环；责任和关键输入可核对。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=dependencies；满足后进入下一必要步骤。

## commit：形成当前承诺

目的：形成当前承诺，形成能继续推进的专业判断。

先读：检查本项目在制量和可做集合。

引导问题示例：“这一小批先推进哪一项，哪些暂留候选？”

Agent动作：区分candidate/next/now，说明取舍与推迟项。预览保存项目索引、milestone.md和task.md，读回后交管执行。

阶段产物及退出：当前一小批承诺符合容量，第一行动具体；后续计划可随结果滚动。

接续：未满足退出条件时只保留实际结论和待问问题，guidance.step=commit；满足后进入下一必要步骤。

## 统一状态与接续

项目、里程碑、任务均使用planned/active/paused/review/completed/cancelled。未开始任务是否可做按输入、负责人、条件、承诺、依赖与容量计算；blocker只记录障碍，不替换推进状态。暂停保存原因、原环节及恢复条件，恢复前重核事实。待验收下只启动work_type=acceptance的试用、核对及补证任务；实质交付返工先将父层回到active。进行中及待验收任务计入在制，受阻不自动释放名额。已完成对象的证据变化先显示需复核，不重写历史；重开保留原验收并记录原因。

文件、字段与公共操作以[能力内治理定义](../../../partners/project-manager/references/governance.md)及其所指程序为准，不能从core/docs取得业务定义。

## 字母阶段任务的过程责任

拆任务前先提出当前里程碑的任务推进阶段候选，说明名称、解决的问题和进入下一阶段的判断，让用户定义或修正。默认A准备、B—Y自定义、Z验收复盘；只建实际需要的阶段。task_stages放milestone.md，task_code与目录采用B1等。公共create-task在锁内按已用最大号追加，取消编号不复用。预览号不占号，提交回执给出实际编号和任务入口；重试用同一operationId。字母不产生硬依赖；当前承诺和可开始另行判断。

任务阶段仍由本基本功引导用户定义；不把编号交互变成反复确认。目标和阶段已确认时直接调用创建接口，不手填任务号和任务索引。不兼容未迁移旧项目，不自动搬迁历史。
