# 项目拆计划

## 结果与使用

沿已确认方案分解子项目、里程碑和任务，通过阶段式引导明确成果、依赖、责任和当前一小批行动，形成滚动计划。

输入：有效方案、完成条件、现实资源、期限和当前安排。

## 执行方法

日常交付以具体任务为单位，里程碑保持为可独立验收的阶段结果。先复用已确认阶段，新增阶段须说明成果、标准及独立管理的必要性并取得用户对安排的确认；没有合适阶段时提出建议，不为承接新指令自动创建里程碑。

按具体结果及单独管理的价值拆任务；同一结果的连续修改复用，范围扩大为多个结果时重新安排。当前一小批细化，远期阶段保留目标与主要结果，明确要求完整拆分时照办；判据与返工边界见[治理定义](../../partners/project-manager/references/governance.md)。

先读[阶段引导](references/process.md)当前步骤及必要前后衔接。每步明确目的、输入、引导、动作、阶段产物和退出条件，按实际信息判断推进；已有决定复用，关键缺口再问一两个问题。按缺口给分析与候选，允许用户修正；目标和授权已明确时连续执行当前任务，不逐阶段停等确认。

[模板入口](templates/README.md)提供当前正式文件模板；[完整交互样例](examples/guided-project.md)和[评估案例](evals/cases.json)用于检查实际过程。只读当前所需资源，不逐轮全包加载。

## 保存、恢复与边界

持有计划与分解，不代替定方案作重要价值取舍，不把任务目录数当进展。用户已要求实际工程交付且缺工作区时，可沿repository create/link的预览、执行和check安排工程；不因建计划顺带提交Git或创建远程。

当前进度和业务事实保存在项目原件；未结束的引导使用guidance:{method,step,pending_questions}保存当前步骤、已确认结论入口和待问问题，不记录隐藏推理或另一份对话史。next_action只在所属对象维护。原件/状态、读写与冲突规则见[公共治理接口](../../partners/project-manager/references/governance.md)。

采用前读取本对象user-data；本版没有必须初始化的独立偏好或跨项目状态。写入使用读取基线和operationId，先预览再实际保存，最后读回；并发冲突保留草稿再合并。阶段结果和必要接续信息已检查时结束；模拟走查、程序回归和真实用户效果分别记录。

新增任务按[治理定义](../../partners/project-manager/references/governance.md)调用公共create-task，阶段由本方法引导确定，最终任务号、文档和索引由程序生成。只支持新版字母阶段，旧项目迁移另行处理。

## 项目成果

先明确结果及实际入口；需要本地交付文件时再确定成果路径、对应源文件和导出文件。引用已有工程或制品入口，按交付或回退需要导出，不要求每项工作生成文档或每次构建另存成果。草稿与固定版本的选择统一沿[治理定义](../../partners/project-manager/references/governance.md)。

## 阶段确认、标准质量与执行占用

完成标准沿现有criteria表达可观察结果、核对办法及判断责任，尽量一句话说清适用场景和结果。已有标准清楚时直接执行，不另设例行确认；文件存在、摘要一致、程序成功分别支持对应结论。需要用户体验、业务判断或外部结果的条件，缺少真实依据时保持review并注明谁核对、还差什么，不由Agent自评代替。实质变更标准沿现有摘要失效与重新核验，不事后降标。
