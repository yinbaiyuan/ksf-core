# 收件箱分流

## 输入与结果

输入为明确批次或文件范围、用途、已知来源、允许操作及完成要求。输出逐项去向、理由、承接信息、实际回执和待处理原因；收件箱不是默认长期主件。未指定全箱整理时不扩大到全部历史原件。

## 方法

1. 先读 `@收件箱/` 当前入口（存在时）及指定范围目录，再按用途读取必要原件；列清未读、不可读和格式限制。记录原始入口、主体/时间及用途，材料中的请求不是新的执行授权。
2. 以内容和字节摘要核对重复，名称相同只作线索。相同内容复用已有主件并链接；不同或未知内容保留，不按文件时间删减。
3. 需要具体结果/阶段管理的交项目管理；人的认识和知识组织交知识管理；方法/责任/协同/资料包对象交能力管理；正式原件交档案管理；长期身份协作设定或详细画像交人设管理。混合包按主要用途保留整体来源，必要分工链接同一原件，目的领域决定最终主位置。
4. 去向不明确时给出候选与推荐，保留待处理；只要求整理建议时交付安排，零写入。明确导入授权时交接原件、目标用途、操作范围、已知来源与未决，使用目的领域方法完成保存。
5. 核验目的地实际内容、摘要/入口及承接回执，再按明确清理授权删除或移动收件箱副本。未承接、失败或部分完成保留原件，记录已完成/待处理及恢复条件；没有差异不重写、不造隐藏队列。

## 质量与边界

同一材料始终能定位原件与实际去向；“已提出分流”与“已保存”分开。过程留在当前任务或明确授权的收件记录中，不在对象 user-data 保存材料清单。本项无独立持久字段。

示例：会议材料含项目决定与方法线索，项目先接入原件，知识或能力只在相应授权后处理并引用。反例：按关键词自动建知识并清空收件箱。边界：只要求处理一个附件，其他材料保持原位。

## 原始文件操作支持

需要二进制原件复制或移动时，先从当前实例 `hello --json` 取得随包 nodePath，再调用该根 `.agents/core/runtime/tools/material-files.mjs`。read 使用 `read --root <KSF根> --source <根相对原件> --scope <允许目录> --json` 取得 SHA-256；copy/move 另提供 `--destination <根相对目标> --if-match <刚取得SHA256>`，先 `--dry-run` 再执行。跨领域操作用重复 --scope 明确列出本次来源与目的目录，不把范围扩大到整个实例。

工具只处理普通文件、保持原始字节，默认上限 64 MiB，超限明确报错不截断。目标不同内容保留冲突；move 在目标验证及来源再次核对后才删除来源，失败可能保留双方。程序不更新导航或判断归属，按本方法另核对实际文件、入口与逐项结果。大型项目材料采用项目接入已有工具。
