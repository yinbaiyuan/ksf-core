# 项目验收与复盘

## 结果与使用

引导回看目标、逐项核验证据、判断达成与差距、分析原因并安排改进行动，形成任务验收和里程碑/项目两级复盘，安全收口与归档。

输入：当前约定的完成条件、对应版本产物、验证范围、执行事实及用户修正。

## 执行方法

任务满足已约定条件时可由 Agent 完成；每个里程碑必须取得用户针对该阶段的明确通过确认。Agent 负责预检、证据与复盘草稿，阶段确认前保持待验收，不把局部成功或停止尝试当作整体验收。

先读[阶段引导](references/process.md)当前步骤及必要前后衔接。每步明确目的、输入、引导、动作、阶段产物和退出条件，按实际信息判断推进；已有决定复用，关键缺口再问一两个问题。按缺口给分析与候选，允许用户修正；目标和授权已明确时连续执行当前任务，不逐阶段停等确认。

[模板入口](templates/README.md)提供当前正式文件模板；[完整交互样例](examples/guided-project.md)和[评估案例](evals/cases.json)用于检查实际过程。只读当前所需资源，不逐轮全包加载。

## 保存、恢复与边界

归档/恢复仅在明确授权下沿project archive/restore的预览、执行、check和引用核对办理；不递归归档子项目。中断先按操作IDrecover核对，后续修改存在时保留现场。项目删除、工程删除、发布、对外发送另按实际授权判断。

当前进度和业务事实保存在项目原件；未结束的引导使用guidance:{method,step,pending_questions}保存当前步骤、已确认结论入口和待问问题，不记录隐藏推理或另一份对话史。next_action只在所属对象维护。原件/状态、读写与冲突规则见[公共治理接口](../../partners/project-manager/references/governance.md)。

采用前读取本对象user-data；本版没有必须初始化的独立偏好或跨项目状态。写入使用读取基线和operationId，先预览再实际保存，最后读回；并发冲突保留草稿再合并。阶段结果和必要接续信息已检查时结束；模拟走查、程序回归和真实用户效果分别记录。

## 归档与恢复过程

收到归档、封存、恢复项目的意图，先完整读取[归档与恢复阶段引导](references/archive.md)，带上已确认结果、授权和当前原件；按当前缺口接续。不要把目录搬迁当作业务收口，也不要把恢复位置当作恢复执行。

## 项目成果

逐项核对目标文件的成果位置、实际可读性、内容与标准、版本和任务引用，必要时固定实际文件摘要；大文件流式核验，不能以存在或摘要正确替代内容验收。旧成果及旧证据沿原入口有效，产出和验收通过分别判断。完整目录职责及历史边界见项目推进搭档的治理定义“项目成果目录与产物归位”。

## 阶段确认、标准质量与执行占用

完成标准沿现有criteria表达可观察结果、核对办法及判断责任，尽量一句话说清适用场景和结果。已有标准清楚时直接执行，不另设例行确认；文件存在、摘要一致、程序成功分别支持对应结论。需要用户体验、业务判断或外部结果的条件，缺少真实依据时保持review并注明谁核对、还差什么，不由Agent自评代替。实质变更标准沿现有摘要失效与重新核验，不事后降标。

里程碑完成统一沿治理check/apply的confirmMilestone意图提交，在同一事务核验来源、确认范围和当前条件，保存复盘user_confirmation及完成状态。工作台来源由宿主提供；对话来源引用实际用户消息、聊天及原生轮次，Agent核对明确阶段通过语义，Core核对真实用户角色及原文。缺少可核验来源先重读或同步，仍缺失保持待验收，可由用户在工作台确认，不擅自开启采集。局部成功、停止尝试或含糊反馈不能扩大为阶段通过。条件、证据及下级结论变化须重新核对；历史已完成记录不批量追认，重开后的再次完成适用新规则。确认记录由Core生成，不手写字段或正文冒充来源。
