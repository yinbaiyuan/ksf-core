# 项目验收与复盘完整交互样例

以下为构造样例，不是真实用户效果或已执行回执。

用户：试讲完成了，帮我复盘。
Agent：先按M1的两个条件核对：课件可讲、练习能独立完成。实际试讲记录显示课件可用，但两位参与者都在练习输入处卡住。因此本次复盘可以完成，里程碑暂不判完成。
用户：问题是样例不清楚。
Agent：这是原因候选。试讲记录确实显示输入说明不清，先修订一个样例并再找一人验证，能区分是说明问题还是练习本身太复杂。改进行动交修订任务，负责人和验证触发写清。
结果：M1/复盘.md记录failed、证据和改进；M1仍保持review，未生成项目完成结论或成果归集包。

## 字母阶段的接续样例

用户：先做方案小样，再实现，最后验收。
Agent：建议A准备：确认本阶段目标；B小样：取得可评审样例；C实现：交付可运行结果；Z验收复盘。每阶段的目标和进入下一阶段判断保存在milestone.md，具体任务用A1/B1/C1/Z1。小样已明确时直接复用，不增加空A任务。
用户：实现中发现小样漏了一项。
Agent：在B组追加下一可用号，保留已有编号；说明对C中哪些任务有真实依赖，独立工作继续。
用户：验收没通过。
Agent：保留本次证据和未通过判断，将必要返工交回对应阶段，之后继续原Z任务；最终结论仍在里程碑复盘原件。
