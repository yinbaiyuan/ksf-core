# 方法如何成立

归属：基本功设计。新建和整体重构时读；这里提供本基本功的专业判断依据。

## 先找能复用的结果

基本功的单位是一个连贯的专业结果，不是一个动词、一种工具或一个角色名。先写出“在条件 C 下，把输入 I 处理为结果 O，用标准 Q 判断好坏”。

若 O 只能解释为另一个方法中无独立意义的一步，把它留在该方法中。若多个 O 需要不同证据、判断权或验收口径，比较拆分。多个搭档可以复用不是硬性门槛；一个搭档持续使用的专业方法也可以成立。

只提供事实和案例集合时使用原资料或数据包；只有加工这些事实的规则成立时才建设基本功。编排多个责任属于协同，持续承接一类责任属于搭档。

## 从差异中找关键判断

记录具体案例的情境、可见证据、当时选择、实际结果及替代解释。比较结果不同的案例：差异来自输入、约束、方法还是执行？比较结果相同但路径不同的案例：哪些步骤必要，哪些只是个人习惯？

一个成功案例只能提供候选线索。没有失败案例时，主动构造会推翻方法的输入，检验它的适用条件。相关性不自动成为因果机制；来自强制规范的规则应按规范适用范围使用，不靠重复故事投票。

## 把知识变成选择

理论名词只有影响选择才进入方法。对每个关键判断回答：

| 问题 | 可交付信息 |
| --- | --- |
| 先看到什么 | 可取得的字段、现象、来源或操作结果 |
| 用什么判断 | 比较口径、专业关系、规范或可解释权衡 |
| 判断后做什么 | 具体动作、分支和它所需的条件 |
| 不能判断怎么办 | 补证、标记未知、可行降级或停止依赖步骤 |
| 如何发现做错 | 可观察的失败信号及对应修正 |

不要把“全面分析、结合实际、确保准确”当作关键步骤。也不要为开放问题虚构精确权重；可以给出有依据的比较顺序和改变选择的条件。

## 固定与开放分别处理

锁定会造成不兼容、数据损失或计算错误的步骤，优先采用已有程序。开放领域保留替代方案、解释及用户取舍，只约束必须满足的结果条件。

方法不授予工具权限；例子中的来源和对象不自动变成当前实例的输入。引用程序时说明真实命令入口、参数、结果和失败处理。没有自动化并不使文字方法无效，只有重复且确定的操作才值得程序化。

## 检验迁移，而非背诵样例

保持结果和主要约束，改变输入规模、表述、材料顺序或非关键条件，方法应仍成立。改变关键条件，方法应切换分支、调整标准或退出。若只能复制例文，先找缺失的判断再增加样例。

质量标准必须对应专业结果。文本结构、格式和引用检查交程序及通用工艺审查；它们不能证明专业推断成立。
