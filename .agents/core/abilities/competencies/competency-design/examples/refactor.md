# 重构样例：从“合计一样”到可解释差异

评估用模拟案例。旧方法和输入是故意设计的缺陷，下面的修改展示诊断到定义的关系。

## 旧定义

“把报价和需求的总额比较，一样就通过，不一样就找销售确认。分析必须全面严谨。”

问题：同额掩盖项目和范围差异；缺少含税口径；未知被压缩成通过/不通过。对应 M3、M4、M7，不是少写几个章节。

## 结构调整

保留独立结果“报价差异核对”，增加项目对应和口径可比条件；未知作为可交付状态。使用完整创建样例中的方法作为基础，下面给出此次聚焦版本的完整候选，不复制额外通用协作规则。

# 报价口径核对

输入报价、交付要求及两者版本。输出逐项差异、计算依据与待确认项。

先核对对象和范围，再按项目而非行号建立对应。总额相同仍检查数量、单位、含税状态和服务范围。

口径明确的项按给定条件复核计算；币种、税率、含税状态或范围不明时保留未知并指出缺口。不得补造税率，不因两份材料文字相近就认定同项。

输出每项的来源、差异性质、影响和修正或补证建议。只有必需项目均可比且无差异才整体通过；其余交付已核对部分和未决。修正后重查受影响项目及汇总。

完成本次可核对结果后结束，不替用户改价或对外承诺。

## 前后结果

同额但缺安装范围：旧方法直接通过；新方法输出范围待确认。税率缺失：旧方法只能泛泛找人；新方法定位缺失字段并继续核对数量和单位。没有改变原本正确的算术规则。

若真实失败只涉及一项舍入误差，应只修该计算与相邻汇总，不默认采用上述整体重构。
