# 能力验证与迭代

## 结果与输入

对确定能力及差异交付可复核的验证结论：实际采用的来源/版本/摘要、案例输入、标准、过程与产物、已证明和未证明部分、失败原因及下一项修订。用于新增、改进、接管或退出能力的质量判断；对象状态、派生、来源与精确引用沿公共契约，不另建质量状态枚举。

必要输入为目标对象、候选差异、预期任务结果、当前定义及可取得案例。旧版、无该能力或已知稳定方法可作基线。没有合适对照时明确只做当前案例验证，不能宣称相对改善；缺少真实案例允许标注的模拟走查，不能冒充真实用户效果。

## 方法

1. **锁定可核对版本。** 读取实际有效定义、依赖和来源摘要，核对本次授权。被审阅不是已采用；真正履责沿公共参与机制记录，缺原生身份保留缺口，不补造。候选未采用前不据其规则扩大权限。
2. **从真实问题选案例。** 优先用户纠正、失败和可复用成功，补一个容易误触发的相邻任务及一个重要缺失/冲突条件。输入保留足够事实和原件入口，去除凭据；单次局部修改不强制昂贵完整评测。
3. **先写标准再观察。** 指定可见产物、关键判断、必须拒绝或降级的条件、允许动作及边界。评判可组合程序、人和有说明的模型检查；不能只检查提示词有没有复述自己的步骤。通用 Agent 已能做好时评估新增规则是否值得。
4. **执行并取结果。** 在适当隔离环境采用指定版本，保留必要轨迹与实际环境结果。Agent 说已预订不等于订单存在；文件存在也不证明内容或实际效果。重复试验仅在随机性、失败或未决风险值得时增加，不为凑数重复运行。
5. **比较与定位。** 比较结果质量、边界遵守、返工、耗时和成本等本次相关指标。区分输入问题、方法缺口、支持故障和执行偏差；没有改善或产生新问题如实保留，不把一次成功推广为稳定规律。
6. **修订并回归。** 只修有证据的问题，按对应设计方法和能力维护落实已授权差异。重验失败场景及受影响相邻场景，后续真实项目记录实际采用及结果，由飞轮复看是否复发。能力正式生效、参与使用和业务结果分开报告。

## 输出、支持与失败修正

结构/引用检查用现有对象 read/check，保存用 write 及版本基线；任务产物、测试或观察记录留在实际项目/能力附属资料，应用不复制一份质量数据库。临时试验不自动建立正式能力，测试不得污染用户业务资产。对象 user-data 无独立持久字段，按公共采用/恢复约定读取即可。

方法参考 [Agent Skills 作者实践](https://agentskills.io/skill-creation/best-practices)的真实任务与轨迹迭代，以及 [Anthropic Agent 评测](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)对环境成果和多种评判的区分；这些是方法依据，不证明 KSF 的实现效果。

模拟正例：改进报价核验后比较旧案例，原来漏掉的税率差异被发现且无错误拦截，记录样本局限。反例：定义 active、check 成功就宣布专业能力成熟。边界例：只有模拟案例，通过后仍明确真实业务待验证。

质量要求为版本可定位、标准与用户结果相关、原件可回溯、失败不隐藏、结论不超范围。无有效证据退回待核对，不通过降低标准制造成功。正常/相邻任务、支持缺失、并发版本、无改善及提前结束分别验证。

## 验证范围的选择

先采用本次明确要求的验证层级。用户要求先完成整体重构、稍后正式诊断或模型对照时，本轮只做必要工程检查并交付实际证据，后续诊断单独安排；不自动调用模型或把未做评测当成创建前置门槛。正式对照至少固定输入、候选版本及可观察用户结果，保留失败样本与基线。
